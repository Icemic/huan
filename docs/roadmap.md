## 0. 工作流程

```
① 读 roadmap（本文件）
② 为本次迭代建迭代文档（docs/iteration/<YYYY-MM>/<YYYY-MM-DD>-<category>-<name>.md）
   写清：目标、范围、设计、关键决策点、验证方式、风险与回滚
③ 执行：编写代码 → 测试 → 顾问 review（反复至无新问题）→ 变异验证
④ 更新 product-design / technical-architecture（若设计变更影响长期结论）
⑤ 回写路线图：标记完成、记录偏差、判断是否需要调整或追加后续项
⑥ 回到 ① 继续下一个迭代
```

**规则**：

- 迭代文档在**开工前**建立（AGENTS.md 的 DDD 要求）；小型维护（拼写、格式）不建。
- 顾问 review 是执行阶段的固定环节：**阻塞意见必须闭环**（核实 → 修复 → 重跑相关验证 → 必要时复审）；非阻塞意见明确采纳或延期记录，不强制无休止往复。
- 变异验证按关键行为与风险采用（不强制每个迭代都做）。
- **计划变更**：常规回写在迭代结束时进行；执行中若发现目标、范围或依赖失效，**先暂停受影响工作、讨论确认并同步更新迭代文档，必要时立即调整本文件**（不以“结束后再改”冻结计划）。
- 分类用 `feat` / `perf` / `bugfix` / `refactor` / `test`（AGENTS.md 定义），按迭代**主要目标**判定。

**决策依据**：D-18（第二里程碑方向）、D-16（内容寻址快照）、D-07（回滚独立于会话树）。

### 2.1 目标

在运行/工具调用边界对受管文件做内容寻址快照，提供变更审查（Diff）与选择性恢复；区分 Agent 改动与用户改动是该能力的价值核心。

### 2.2 范围（详细）

1. **内容寻址快照后端**（D-16）
   - blob（按内容 hash）+ manifest（路径 → hash + 元数据）；存储在应用数据目录，**不写入工作目录**；
   - **存储位置的具体形态**：应用数据目录的具体路径、多工作区/多应用的隔离方式、对象库与 manifest 的目录布局（迭代设计时定）；
   - 增量扫描：run 起止 / 工具调用前后，只扫描受管文件的差异；
   - 忽略策略：默认尊重工作区忽略约定（`.gitignore` 等）+ 内置排除（对象库自身、`node_modules` 等）；
   - 边界细化：未跟踪/忽略文件的处理、重命名识别、符号链接、权限位、大文件阈值（**迭代设计时定**）；
   - 孤儿 blob 回收（对象库可独立重建，manifest 带格式版本）。
2. **ChangeSet 与 manifest diff**
   - ChangeSet = 两份 manifest 之差 + 元数据（来源 run/tool、时间、操作者）；
   - 归因：基准快照与变更后快照对比 + run/tool 元数据 → 区分 Agent 改动与用户改动；
   - 不做 Git 依赖、不碰用户 index/暂存区（Git 未来仅可能作为加速层）。
3. **Provider 契约落地**（`@huan/history`）
   - 接口：`capture` / `diff` / `restore`（技术架构 §5.3 草案）；
   - 必须能表达：不支持恢复、部分成功、冲突、需用户确认、恢复中断；
   - 选择性恢复能力由 provider capability 声明，公共层不假定所有实现能力相同。
4. **Monaco Diff 审查视图**（D-21）
   - 文件树 + 文本 Diff + 二进制变化摘要 + 冲突提示；
   - 先文件级接受/撤销，hunk 级后续；
   - worker 资源在桌面壳下需按打包方式配置（与 M4 的桌面宿主评估联动）。
5. **选择性恢复 + 冲突检测**
   - 恢复前比对待恢复文件的实际内容与快照元数据；
   - 检测到外部改动时展示冲突并允许取消，**不静默覆盖用户修改**；
   - 明确声明不可恢复范围：Shell 副作用、网络请求、数据库写入等。

### 2.3 关键约束

- **禁止把「跳转 Pi 旧会话节点」等同于「项目自动回退」**（D-07）：两者是显式、可独立执行的操作；组合命令需处理未保存改动、运行中的 Agent 与冲突。
- 文件树与快照忽略策略**共享同一套判定**（技术架构 §6.2）。
- 命名：与末语工坊的 checkpoint（marker 映射）概念区分，本项目一律用「快照 / FileSnapshot」措辞（产品设计 §5.7）。

### 2.4 风险

| 风险 | 应对 |
| --- | --- |
| 快照性能（大仓库扫描） | 增量扫描 + 忽略策略先行；必要时评估 Git 加速层（不作为依赖） |
| 恢复语义在「运行中 Agent」下不安全 | 与运行状态联动：运行中禁用恢复或要求先中止（迭代设计时定规则） |
| Monaco 体积与 worker 配置 | D-21 已接受；延迟加载 + 按需构建 |

## 3. M4 日用强化

### 3.1 目标

把 Harness 变成日常主力工具：Pi 生态兼容到位、代码浏览可用、交互按真实痛点打磨。

### 3.2 范围（详细）

1. **Pi 配置/扩展生态兼容**
   - 对照 Pi CLI 的加载行为：SDK 不自动加载 CLI 内置扩展（`codemode` / `tool_search` / MCP），需显式装配（迭代③已部分完成，需系统性对照）；
   - 升级 Pi 版本前的回归清单（技术架构 §8）；
   - Skills / Prompt 模板 / MCP 的加载与呈现（当前不暴露，需补齐「按配置加载 + 敏感操作执行前呈现」）。
2. **文件树与代码浏览**
   - 工作目录选择、文件树（忽略规则与快照策略共享判定）；
   - Monaco 查看（只读）；
   - 布局：可拖拽分栏（文件树 / 查看 / Diff / 聊天区）。
3. **交互打磨**（按真实使用痛点，不预设清单）
   - 输入体验、快捷键、长列表虚拟滚动、大文件查看性能；
   - 会话管理手感（切换、搜索、归档）；
   - 附件能力扩展（当前仅图片 passthrough，按需求评估）。

### 3.3 关键约束

- 性能：流式更新不阻塞输入；大文件查看不卡 UI；长列表虚拟滚动（产品设计 §6）。
- 可访问性：常用操作有键盘路径；文案经 i18n（D-22/D-25）。

### 3.4 退出标准（待迭代设计时细化）

1. 日常使用中不再需要回退到 Pi CLI 完成基本操作（自评）；
2. 文件树 + 查看 + Diff + 聊天四区可同时使用，大文件不卡 UI；
3. Pi 配置/扩展加载行为与 CLI 对照测试通过。

## 4. M5 末语工坊接入

**决策依据**：D-01（两应用独立）、D-08（不提供任意文件/Shell 工具）、D-17（编码前细化边界）、D-20（威胁模型）。

### 4.1 目标

验证「公共库支撑两个不同应用」的中心假设；产出第二个消费方，暴露抽象失配。

### 4.2 范围（详细）

1. **Editor Bridge**：编辑器服务接口（业务层/store actions），不直接读写磁盘文件；
2. **编辑器上下文工具**：只读上下文（场景树、选中对象、资源索引、校验结果）+ 写入操作（增删节点、改属性、绑定资源）+ 交互能力（选择对象、确认批量修改）+ 辅助能力（预览、校验）；
3. **专用 Tool UI**：按 `toolName` / `rendererId` 注册自定义卡片；**必须有通用回退**（历史会话不因组件缺失不可读）；
4. **事务撤销适配**：写入操作经编辑器 Undo/Redo 体系，不绕过既有校验与通知。

### 4.3 关键约束（产品设计 §5，长期有效）

1. 不提供通用 `bash`、任意路径 `read`/`write`/`edit`；文本能力走受控专用 API；
2. 资源上下文支持**未写盘状态**（不以磁盘文件为唯一数据源）；
3. 工具执行不绕过编辑器既有校验、通知与 Undo/Redo；
4. 资源加载受控：**不把用户通用 Pi Extension 目录的任意代码引入受限 Agent**（D-20 的核心威胁面）；
5. 编辑器主线程不被 Agent 长任务阻塞；异步工具考虑 UI 生命周期；
6. 威胁模型：防误操作 + Prompt Injection 围栏；**不承诺 OS 级沙箱**（升级项见 §5.3）。

### 4.4 前置条件

- M5 **启动前**：依据末语工坊实际文档与代码细化边界（D-17）；
- 公共库的每个接口以「两应用可用」为设计评审约束（D-17）——这是 M2~M4 期间持续生效的约束。

### 4.5 退出标准（待迭代设计时细化）

1. 末语工坊内可完成一次完整的「读上下文 → 改场景 → 撤销」闭环，且**未保存状态下读取/修改/撤销正确**；
2. 缺少专用 Tool UI 时，历史会话仍可读（通用回退生效）；
3. 编辑器 Agent 不持有任意文件/Shell 工具（工具面仅编辑器 API）。
