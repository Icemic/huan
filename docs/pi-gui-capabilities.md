# Pi 基础能力 GUI 化：范围与验收规范

**最后更新**：2026-10-31

**运行基准**：`@earendil-works/pi-coding-agent@1.4.0`（仓库实际安装版本）

**版本沿革**：由 1.1.0 升至 1.4.0，实施与回归见[G1.1迭代](iteration/2026-10/2026-10-31-feat-user-space-reliability.md)。

**用途**：持续约束 huan 的 Pi GUI 能力范围与验收，防止实施偏离。

## 1. 目标与维护方式

目标：使 Pi 自带的交互基础能力在 huan GUI 中可用，能够取代 Pi TUI 进行项目工作，随后以 huan 开发 huan。基础能力按 Pi 本身盘点，不按用户近期使用频率删减。

| 信息 | 唯一维护位置 |
| --- | --- |
| 能力定义、GUI 等价语义与验收要求 | 本文 |
| 实施排序、当前任务、能力完成状态、阻塞与延期决定 | [roadmap.md](roadmap.md) §2 |
| 长期产品与架构约束 | [product-design.md](product-design.md)、[technical-architecture.md](technical-architecture.md) |
| 当前限制与历史索引 | [todo.md](todo.md) |
| 单次设计、源码盘点与验证证据 | [iteration/](iteration/)；首次盘点见 [范围迭代](iteration/2026-10/2026-10-31-feat-pi-gui-scope.md) |

维护规则：

1. 每个功能迭代列出涉及的能力 ID，开工前核对本文及 roadmap。
2. 完成时在 roadmap 关联能力 ID 与迭代证据；本文只在验收要求变化时更新，不另存进度表。
3. 发现缺漏的 Pi 原生能力时先补入本文，再安排任务。删除、降低要求或延期需用户确认并记录原因。
4. 升级 Pi 时重新比对仓库安装包的文档、CLI 行为、SDK 声明与示例，明确新增、变化和不适用项。
5. SDK 缺少公开接口或能力依赖终端时记录阻塞和适配方案，不静默删项，也不把文本发给模型冒充执行成功。

## 2. 范围与原则

### 2.1 包含

- Pi 原生会话、树导航、分支、上下文管理、模型与认证、工具执行及输入控制。
- Pi 用户/项目配置、指令、Skills、Prompt 模板、内置扩展与 MCP 的加载、使用和维护入口。
- 复制、导入导出、分享、诊断等原生操作；条件能力在条件满足时可用。
- 默认 Pi 用户空间和手工指定其他目录；自动化测试使用隔离空间。

### 2.2 延后与等价替换

huan 已确认增加多项目工作区：会话归属工作区而非单项目，成员动态管理与跨项目工具操作属于基础使用范围。它是 huan 在 Pi 之上的组织能力，规范见[独立设计](iteration/2026-10/2026-10-31-feat-multi-project-workspaces.md)，不代表下表的文件树与 IDE 工作台提前实施；相关 Pi 适配仍须满足 ENV-02/03、SES-01/02、RUN-03/06 与 RES-01。

| 事项 | 边界 |
| --- | --- |
| 文件快照、回滚、ChangeSet、变更来源 | huan 新增能力，延后；会话树导航不恢复项目文件 |
| 文件树、Monaco、Diff 工作台、末语工坊 | 不作为 Pi GUI 验收条件；文件引用和路径补全仍在范围内 |
| 桌面壳、分发、OS 沙箱 | 继续用浏览器 + Node 验证；出现基础能力阻塞时重新评估 |
| 终端布局、ANSI 主题、终端图像协议 | 用 GUI 的阅读、输入和设置能力替代，不逐项复制终端渲染参数 |
| llama.cpp 管理（MOD-05） | 经用户确认排除，不装配 `/llama` 管理扩展，不提供 router 状态、模型加载/卸载与下载等专用管理入口；不改变通用模型目录、认证与调用能力 |
| 第三方任意 TUI 组件 | 范围内的基础Pi内置功能须提供React等价入口；其他TUI组件不支持时明确提示 |

命令名称是行为索引，不强制逐字保留为 slash 输入；可用命令面板、按钮或专用页面承接。普通输入、内置命令、扩展命令、模板与Shell输入须按 Pi 语义路由，保留扩展处理和覆盖规则。

## 3. 能力对照与验收要求

下表定义验收目标，不表示当前已实现。当前源码盘点及 SDK 证据见范围迭代；实际完成状态仅看 roadmap。SDK 接入描述是已知路径或调研方向，不承诺所有 CLI 功能都有同名公开 API。

### 3.1 用户空间与项目

| ID | Pi 基准 / 接入方向 | GUI 要求与关键验收 |
| --- | --- | --- |
| ENV-01 | `agentDir`、`PI_CODING_AGENT_DIR`、标准资源发现 | 默认复用 Pi 空间（默认 `~/.pi/agent`）；允许手工指定其他目录；显示当前目录和生效来源；启动不依赖先运行 TUI |
| ENV-02 | `SessionManager`、sessionDir setting / 环境变量 | 配置与会话位置规则明确；指定用户空间时默认会话也归入该空间；显式 sessionDir 覆盖的优先级及共享范围可见；创建、枚举、打开、分支、导入与删除使用一致规则，不误操作另一空间 |
| ENV-03 | cwd、`/trust`、`ProjectTrustStore` 与装配上下文 | 从 GUI 选择/输入项目路径、切换和再次进入；显示 cwd；加载受保护项目资源前处理信任；拒绝、保存及重启后的结果与 Pi 一致，信任不等于沙箱 |
| ENV-04 | 隔离运行与 SDK 配置注入 | 默认自动化不读取或修改个人凭据/会话，不依赖个人模型；初始化失败可清理；个人环境验证单独显式运行 |

### 3.2 会话与分支

| ID | Pi 基准 / 接入方向 | GUI 要求与关键验收 |
| --- | --- | --- |
| SES-01 | `/new`、`/resume`、continue、`SessionManager` | 新建、打开、继续最近会话；正确恢复 cwd、活动分支、模型与消息；服务重启后可继续 |
| SES-02 | 会话选择器、`/name` | 搜索、命名、删除，显示路径与活动时间，支持排序及已命名过滤；保留已有归档入口并明确其持久化行为；搜索范围明示，已有标题过滤不等于全文搜索 |
| SES-03 | `/session`、`getSessionStats`、`getContextUsage` | 查看会话 ID/文件、消息与上下文用量、累计 token 和费用；压缩后统计仍正确，区分分支上下文量与累计计费量 |
| SES-04 | `/tree`、`getTree`、`navigateTree` | 展示活动节点、标签与过滤；切换用户节点按 Pi 规则恢复编辑文本，其他节点从目标后继续；保留旧分支，支持离开分支时的摘要选择与取消 |
| SES-05 | `/fork`、runtime `fork` | 从选定历史用户消息创建独立会话，恢复所选文本；父会话保留；扩展取消及失败不伪报成功 |
| SES-06 | `/clone`、核对 CLI 组合路径 | 从当前位置复制活动分支到新会话；不误复制全部废弃分支；新旧会话可以独立继续 |
| SES-07 | `/import`、runtime `importFromJsonl` | 导入并继续 JSONL；路径不存在、格式错误、缺失 cwd 有反馈；不覆盖原始导入文件；按目标用户空间存储 |

### 3.3 对话、输入与执行

| ID | Pi 基准 / 接入方向 | GUI 要求与关键验收 |
| --- | --- | --- |
| RUN-01 | `prompt`、消息与工具事件 | 正确展示流式文本、Thinking、工具参数/输出/错误和图片；折叠、复制与长输出可读；历史重开无专用渲染器仍可读 |
| RUN-02 | steer、follow-up、clearQueue、abort | 可选择转向或后续排队，查看并整体取回队列；中止不误报失败；取消与取回行为对照 Pi，输入不丢失、不重复投递 |
| RUN-03 | `@` 文件引用、路径补全、图像输入 | 从服务端工作区选择/搜索文件并补全路径；图片选择、粘贴/拖入与模型能力校验；浏览器本地文件和服务端路径明确区分 |
| RUN-04 | `!` / `!!`、`executeBash`、`abortBash` | 用户直接执行命令、实时查看输出并取消；`!` 纳入模型上下文，`!!` 排除；命令不是发给模型后等待它代执行 |
| RUN-05 | 自动重试、压缩与结算事件 | 运行、等待工具/交互、压缩、重试、取消和失败状态可区分；自动继续未结束前不提前显示空闲 |
| RUN-06 | 权威快照、SSE 与多订阅 | 首连、断流、关闭后再连、刷新和多窗口恢复一致消息/分支/队列/交互状态；窗口关闭不终止运行，不漏离线历史 |
| RUN-08 | huan内置SDK子agent（独立扩展能力） | 同进程独立上下文，支持单个、每调用最多8项/4并发与链式；沿用agents定义及已确认模型/工具/工作区规则。完整子记录可从父工具只读查看、刷新后保留且排除普通会话列表；支持逐任务取消及子任务Host UI应答，父工具计入委派用量。禁止嵌套，huan内同名工具固定使用SDK实现，运行不依赖外部Pi CLI |
| RUN-07 | 多行输入、历史、编辑与快捷操作 | 提供多行、输入历史和草稿恢复，错误后内容可找回；高频操作有键盘路径；编辑历史消息遵循分支语义，不覆盖已提交记录；长文本直接在多行输入框编辑 |

### 3.4 模型、认证与上下文

| ID | Pi 基准 / 接入方向 | GUI 要求与关键验收 |
| --- | --- | --- |
| MOD-01 | `/model`、`/thinking`、`/scoped-models` | 实际目录、刷新、选择、范围配置与切换；级别跟随模型能力，核对 1.1.0 的 `max` 与当前协议差异；显示不可用和回退原因 |
| MOD-02 | `/login`、`/logout`、`ModelRuntime` | API key/OAuth 的状态、输入/打开授权页、回填、取消和退出可在 GUI 完成；凭据保存在所选空间，日志和普通快照不泄露密钥 |
| MOD-03 | `/settings`、`SettingsManager` | 可修改 Pi 常用行为设置，区分用户/项目/会话与临时覆盖；其余非终端设置可通过 GUI 编辑配置并验证；明确保存、重载或重启要求，不静默丢弃未知字段 |
| MOD-04 | `/compact`、`compact` 与自动压缩 | 手动压缩可附指令；支持设置自动压缩、显示过程与失败恢复；原始历史仍可访问；取消及并发操作安全 |
| MOD-05 | `/llama`、1.1.0 内置 llama.cpp 扩展 | 经用户确认排除；保留稳定 ID 供范围追踪，不属于 GUI 验收项，边界见 §2.2 |

### 3.5 资源、命令与 Host UI

| ID | Pi 基准 / 接入方向 | GUI 要求与关键验收 |
| --- | --- | --- |
| RES-01 | ResourceLoader、指令、system prompt、Pi packages | 按用户/项目规则发现并展示生效的指令和资源、来源与诊断；沿用已配置 packages 的加载规则，执行代码前遵循项目信任 |
| RES-02 | `/`、模板、`/skill:name`、扩展命令 | 命令目录、参数提示、补全和调用；模板展开与 Skill 加载保持 Pi 语义；资源重名及覆盖与 Pi 一致，不能把所有 slash 命令都当普通 prompt |
| RES-03 | `/reload`、`AgentSession.reload` | 重载设置、指令和资源并更新 GUI 目录；旧交互和订阅正确结束，MCP 不泄漏子进程；终端专属资源按 GUI 边界处理 |
| RES-04 | `ExtensionUIContext` | confirm/select/input/editor、通知、状态及必要编辑器操作可用；取消/超时/重复应答明确；不能以无声空实现代替基础交互 |
| RES-05 | CLI builtins、SDK extensionFactories | 显式装配所需 MCP、codemode、tool search 及其他内置能力；按 Pi 配置启停及替换，默认工具选择与 CLI 一致；验证嵌套工具进度和父子关系 |

### 3.6 MCP

huan 的 MCP 集成层为 `@huan/mcp`，依赖官方 `@earendil-works/pi-mcp` 协议库，与 Pi 内置 MCP 集成同层；不引入 `pi-mcp-adapter` 等第三方替代品。用户配置存 `<agentDir>/mcp.json`，项目配置存 `<cwd>/.pi/mcp.json`，与 Pi TUI 共用服务器定义及配置语义；持久化更改会影响双方后续加载，保存与运行时应用分开。OAuth 凭据和日志分别使用 `<agentDir>/huan/mcp-auth.json` 与 `<agentDir>/huan/mcp.log`，不共享 Pi 的认证/日志文件；huan 专属设置独立存储。未来实现路线的调整由 roadmap 维护，下列验收语义不因路线而降低。

| ID | Pi 基准 / 接入方向 | GUI 要求与关键验收 |
| --- | --- | --- |
| MCP-01 | Pi 共享 `mcp.json`、`@huan/mcp` | 用户与受信项目配置加载、覆盖及校验遵循 Pi 语义，共用用户/项目文件并保留未知字段；stdio / streamable HTTP 可连接，配置错误不阻断其他服务器；无受支持服务器时可正常使用 Pi |
| MCP-02 | `/mcp` 状态、工具与资源 | 展示连接、配置来源、工具/资源与错误，模型可发现并调用工具及读取资源；支持连接中的状态与动态工具列表变化 |
| MCP-03 | `/mcp` 启停、重连与 exposure | GUI 可启停、重连、调整服务器和工具暴露；保存到正确来源，项目 override 与会话临时注册区分；hidden/deferred/codemode/direct 语义正确 |
| MCP-04 | MCP OAuth | GUI 完成登录、退出、重定向回填和错误恢复；认证按服务器身份与 URL 隔离，凭据不通过普通消息泄露 |
| MCP-05 | 配置维护、reload、shutdown | GUI 可新增/修改/移除服务器配置，保留无关字段并提示共享影响；revision 拒绝已过期提交，但不承诺与 Pi 跨进程同时写入的原子 CAS；重载/换会话/退出正确回收连接和子进程；用本地测试服务验证，不依赖私人服务 |

### 3.7 输出、诊断与 GUI 等价入口

| ID | Pi 基准 / 接入方向 | GUI 要求与关键验收 |
| --- | --- | --- |
| OUT-01 | `/copy`、`/export` | 复制回复或选中文本，导出 HTML / JSONL；可选择或取得产物，保持 Pi 活动分支语义；导出前提示敏感内容 |
| OUT-02 | `/share`；1.3+ 的 `sessionShareDestination` | 复用 Pi 原生分享目标与条件，支持对应版本的目标选择；上传前预览/确认，返回可打开链接，缺认证或外部依赖可诊断；不自行引入 huan 分享服务 |

## 4. 验收与防偏离要求

### 4.1 单项完成标准

一项能力需要同时满足：

1. 有可发现、可操作的 GUI 入口，且后端实际执行对应行为。
2. 成功、取消、失败和需要等待的状态可见；相关操作的运行中准入与并发规则明确。
3. 涉及持久化、树切换或重连时，有权威状态恢复验证，不仅是本地乐观展示。
4. 相关自动化与类型检查通过，迭代文档记录证据；条件能力覆盖具备和缺少前置条件两种情况。
5. roadmap 记录验收结果及关联迭代；仅有 SDK 接口、协议或组件不算完成。

### 4.2 整体完成标准

- 本文全部适用能力通过单项开发验收；例外必须有用户确认的范围决定。
- 默认与自定义用户空间都有自动化覆盖；默认测试无需个人凭据或私人扩展，个人环境兼容验证显式运行。
- 不要求用户返回 TUI 完成基础操作；认证浏览器、Shell 环境和原生分享服务等必要外部依赖不等于依赖 TUI。
- 自迭代场景：在 huan 进入自身仓库，恢复会话、阅读/修改代码、执行测试、探索分支、使用测试 MCP、中止/排队，重启后继续。
- 桌面手工与平台验证不阻塞开发迭代完成；发现问题建立新迭代。手工结果记录为产品可用性证据，不虚构为已执行。

### 4.3 范围审查

每次评审回答：本次解决哪个能力 ID？是否引入 Pi 已有机制的重复实现？是否混入文件回滚、完整 IDE 或桌面分发？新增抽象有无当前消费方？条件能力是否被“暂时没用”替代验收？
