## 1. 产品定位

幻（huan）是一个可内嵌的高度定制化 AI Harness，基于 Pi Coding Agent 生态构建，专为开发者本人日常使用设计，并保留嵌入其他应用的能力（首位候选：末语工坊）。

它以 SDK 嵌入路线提供 Pi Agent 的 GUI，使 Pi 基础交互能力可在图形界面使用，取代日常 Pi TUI 工作流，并支持用 huan 开发 huan。长期保留代码工作区、审查与文件快照等增强方向。

基础能力范围与验收要求见 [Pi GUI 能力规范](pi-gui-capabilities.md)，实施排序与状态见 [路线图](roadmap.md)。

### 两种使用形态

| 形态 | 说明 | 状态 |
| --- | --- | --- |
| **独立通用 Harness 应用** | 日常 AI 编程与项目维护：多会话、代码工作区、Diff 审查、Checkpoint 回滚、Pi 扩展生态 | **首个交付对象** |
| **末语工坊内嵌 Agent** | 编辑器内的 Agent：经编辑器 API 读取/修改场景、资源、脚本，无任意文件与 Shell 权限 | 设计约束参与，后续接入 |

两者是**相互独立的应用**（D-01）：各自独立打包、部署、更新与配置；只共享库（`@huan/*`）、协议与实现范式，**不共享**运行中的 Agent 实例、进程与会话数据库（D-02）。

### 边界原则（长期有效）

1. 复用机制，不强制共享业务语义：运行时控制与 UI 基础留在公共库，具体工具、数据、回滚实现留在应用。
2. 优先组合 Pi，不重新包装：不在公共库另造 Pi 已有概念的等价物。
3. 数据只有一个权威来源：Pi 会话由 Pi 管；编辑器项目状态由编辑器管；前端是投影而非第二权威。
4. 后端执行与前端渲染分离：UI 不决定工具是否可用；Tool UI 缺失时历史仍可读。
5. 失败和恢复是正常路径：断线、重载、中止、超时、部分回滚都有明确语义。
6. 先完成实际功能流程，再根据消费者拆分公共包，禁止仅凭想象引入复杂通用接口。
7. 独立GUI的运行能力通过内嵌Pi SDK承接，不要求另行安装或运行Pi CLI。Shell、资源包管理及MCP服务器的外部程序需求按功能分别说明；共享配置或加载扩展不构成CLI/TUI扩展自动兼容的承诺。

## 2. 目标与非目标

### 2.1 目标

- **G1 可复用的 Pi 运行时集成**：启动/销毁、事件订阅、会话选择、发送、取消、Steer/Follow-up、模型切换、配置注入，保持 Pi 原生语义。
- **G2 完整而可定制的 React 聊天体验**：流式文本/Reasoning、工具调用状态、错误、输入队列、自定义 Tool 卡片；应用可定制布局与主题。
- **G3 应用集成**：应用按自身方式注册工具、承接 Tool UI、处理人机交互请求。
- **G4 可演进的检查点与审查能力**：回滚与 Diff 独立于 Pi 会话存储语义。
- **G5 清楚的权限边界**：编辑器环境从运行时资源与进程权限层限制任意文件/命令访问，提示词只提供行为约定。
- **G6 对 Pi 的兼容性可测试**：日常交互对标 Pi CLI；公共层可升级、可替换。

### 2.2 非目标（首期）

- 不实现新的模型适配器框架或自有 Agent Loop，不取代 Pi SDK。
- 不追求两个应用跨进程共享 Agent Session，不要求共享用户数据与全局配置。
- 不做供任意第三方应用即时装配的完整插件平台；只预留清晰扩展点。
- 不承诺 Shell、网络请求、安装依赖等外部副作用可原子撤销。
- 任意第三方扩展的终端TUI需要专门适配。范围内的 Pi 内置基础功能提供 GUI 等价操作；终端显示参数用 GUI 能力替代，CLI 自动化模式不作为交互 GUI 的验收项。
- 不提供 llama.cpp router 的专用管理入口（`/llama`、状态、模型加载/卸载与下载等）；通用模型目录、认证与调用沿用 Pi SDK。
- 不将文件 Diff 与编辑器场景 Diff 强行统一成一种数据结构。

## 3. 核心能力与功能范围

### 3.1 会话与对话（首期）

- 多轮对话、流式文本与 Reasoning 展示、工具调用进度卡片（通用回退渲染）。
- 运行中 Steer（转向）与 Follow-up（排队）：消息输入队列，可整体清空并恢复到输入框。
- 中断执行、错误展示与重试。
- 会话管理：新建、继续、搜索、重命名、归档、删除；会话信息、tree / fork / clone 与 JSONL 导入均属于 Pi GUI 基础范围。Pi 会话树是权威，会话导航不隐式恢复项目文件。会话树面板按需展示实际条目、标签与活动路径，支持对话/工具/全部/已标记过滤；纯工具调用记录归工具，带对话正文的助手消息保留在对话中；单链平铺，分叉处增加缩进并可折叠，首次打开仅展开当前路径，搜索临时揭示命中分支，列表按可见行虚拟渲染；历史用户消息可直接定位对应树节点。历史用户消息与树用户行可 fork，上下文栏可 clone 当前活动路径到独立会话；两者只让发起窗口切换，父会话与其他窗口保持原状。
- JSONL 导入支持服务端绝对路径与浏览器上传，预览显示源 ID/cwd/条目/目标目录/冲突，源 cwd 不可用时必须显式选择工作区成员作为替代目录。默认保留源 ID 与完整树；同 ID 内容不同需明确选择“作为新会话导入”（新 ID、保留完整树与父会话血缘）。导入前提示敏感内容且不上传第三方，确认时重读源并走项目信任入口，不替换当前会话。
- 列表支持全部/当前工作区范围、活动/创建时间和名称排序、仅命名过滤；搜索明确限定名称和首条消息。归档为 huan 持久化组织标记，不停止任务；删除须显示会话路径并确认。只读详情区分全文件累计 token/费用与活动分支上下文，查看冷历史不执行项目扩展。树导航可选不摘要/摘要/自定义指令，摘要可能计费且可取消；运行中提供“停止并跳转”，取回队列保留为草稿，须由用户再次发送。成功后所有窗口更新权威历史与活动节点，返回的编辑器文本只进入发起窗口，其他窗口保留本地草稿。
- 模型与 Thinking 级别切换（每会话），上下文用量显示，只读清单与冷会话快照查看。输入区左侧提供独立模型、思考强度与会话操作按钮，行内按钮高度统一为28px，发送/停止居右；思考强度修改成功不额外提示。统一设置“模型与服务商”页管理Pi用户enabledModels全局范围；工作区管理可自定义覆盖或跟随全局，输入区只展示最终候选，按模型声明提供完整Thinking级别（含max）。已有会话继续使用原模型，范围变化不触发自动切换或发送拦截。
- 运行操作面板直接执行用户Shell并展示实时输出，可独立取消；纳入上下文与仅保留历史可选，固定cwd执行且不提供沙箱。手动上下文压缩支持附加指令与取消，原始会话树保留；自动压缩开关保存用户默认并说明项目覆盖。
- Host UI（人机交互）：会话待答请求集中显示在输入区上方，保留工具关联身份，工具过程行显示等待交互状态；请求不会随工具折叠隐藏。独立请求同样可直接应答（D-19）。启动期信任和session_start请求用全页面服务交互Dialog，可在其他窗口接管；通知、状态与文本widget可见。扩展编辑器修改由目标窗口主动应用，旧文本可恢复，不覆盖其他窗口草稿。
- 输入区通过`/`提供悬浮命令目录与参数补全，通过`@`悬浮补全引用成员文件，通过`!`/`!!`直接执行Shell；图片选择收在`+ → 添加图片`，保留粘贴和拖入。图片不兼容模型时保留输入与附件。文字草稿按窗口/会话恢复，多行内容直接在输入框编辑，历史消息编辑沿用独立fork；运行中可选转向/后续并整体取回。
- 断线重连：以权威快照恢复，不要求事件重放。
- 消息流中的read/write/edit/bash按文件内容、实际编辑差异、命令与输出分别展示，完整参数、原始结果及未知字段可查。过程主文字和代码14px、次要数据12px；用户Shell使用右侧muted标题表达来源，取消与失败明确区分，复制保留原文。

- 消息代码统一使用Shiki：Markdown按显式语言，read/write与替换片段按路径，实际补丁按hunk的两侧文件代码高亮并保留增删背景，Shell命令用bash，参数和详情用JSON。配色跟随浅色、深色、One Dark及Solarized Light；未知语言保持文本，超长单行保留原文，其余行继续高亮。普通代码复制取原始内容，终端复制为去ANSI的可读文本。官方彩色括号按完整代码匹配；两种Shell保留新执行输出的ANSI，支持接受FORCE_COLOR的CLI默认输出颜色，尊重NO_COLOR与显式FORCE_COLOR。

- **多窗口并发**：可同时打开多个 Web 窗口查看与操作同一会话；消息、运行状态、Host UI 请求全窗一致，任窗口断开不影响其他窗口与运行中任务；窗口本地视图状态（选中项、输入草稿）各自独立。

### 3.2 多项目工作区与代码查看

**已确认的工作区模型（已实现）**：一个工作区包含一个或多个项目目录，项目可属于多个工作区；会话显式归属一个工作区，左侧按工作区一级、会话二级组织。工作区管理提供名称、成员别名与路径、动态增删和状态提示。

新会话选择一个成员作为起始 cwd，默认使用窗口上次选择，创建后保持固定；跨项目通过明确的项目路径与 Shell cwd 操作。成员变更在正在进行的运行结算后、下一轮开始前生效，移除不删除文件或历史。只从起始目录装配项目设置、扩展和 MCP，其他成员提供目录与项目指令，成员关系不等于代码执行许可或 OS 隔离。设计依据见[工作区迭代](iteration/2026-10/2026-10-31-feat-multi-project-workspaces.md)。

工作区定义和会话关联属于 huan 自有数据，默认保存在所选用户空间的 huan 子目录；不要求与 Pi TUI 的工作区同步。参考 pi-workspaces 并选择性复用路径与工具源码，用户无需安装该插件。存储和复用细节见上述迭代设计。

以下代码查看能力继续作为后续增强：

- 工作区成员目录的文件树（忽略规则跟随工作区约定）。
- 代码查看与 Diff 审查：Monaco 全套（D-21），先文件级接受/撤销，hunk 级后续。
- 变更来源：Agent 改动与用户改动分开呈现（见 §3.3）。
- 未来可扩展为手动编辑（Monaco 保留上限）。

### 3.3 文件快照与回滚（增强能力）

- 在运行/工具调用边界对受管文件做**内容寻址快照**（blob + manifest），不依赖工作目录是 Git 仓库（D-16）。
- ChangeSet：两份 manifest 之差 + 元数据（来源 run/tool、时间、操作者）。
- 审查：文件树 + 文本 Diff + 二进制变化摘要 + 冲突提示。
- 恢复：按文件接受或撤销；恢复前检测外部改动，**不静默覆盖用户修改**。
- 明确声明不可恢复范围：Shell 副作用、网络请求、数据库写入等不受 Provider 管理的操作。
- 会话树跳转与项目回滚是**显式独立操作**，可组合但不隐式联动（D-07）。

### 3.4 扩展与配置（持续）

- 兼容 Pi 用户配置与认证体系（SDK 与 CLI 的加载差异需显式装配并测试，见技术架构 §8）。
- 扩展、Skills、Prompt 模板与 Pi 内置能力按配置加载，提供资源发现、命令调用及重载入口。
- MCP 的连接、工具/资源、启停、重连、认证与暴露方式有 GUI 等价操作；独立 `@huan/mcp` 集成层依赖官方 `pi-mcp` 协议库，不引入第三方 MCP 替代品，可按产品需求演进或切换到完善后的官方集成。MCP 用户/项目服务器配置与 Pi TUI 共用，持久化修改会影响双方后续加载；OAuth 凭据、日志和 huan 专属设置独立存储，运行实例相互独立。路径与验收见能力规范。管理面板按服务器、配置和认证组织；临时启停/暴露只影响本会话，持久编辑通过共享配置草稿保存后显式应用。关闭面板不取消OAuth，可从另一窗口继续回填；原文与回填不进入普通消息。
- 默认沿用 Pi 用户空间（默认 `~/.pi/agent`），允许手工指定其他目录；项目 `.pi` 资源按 Pi 项目信任规则加载。
- 顶栏统一设置采用外观、模型与服务商、对话、工具与资源、MCP、高级、服务与诊断七个垂直页签。用户settings.json各页共用一份草稿与保存；MCP文件独立保存，主题即时生效。项目配置从工作区成员入口打开，实际资源与MCP连接从会话菜单进入；全局配置访问不依赖会话或目录。界面组合使用官方shadcn base-nova组件，来源见应用第三方说明。
- 内置subagent在同一服务内创建独立SDK上下文，支持单个、并行与链式委派。完整子记录从父工具只读打开，刷新后保留，不进入普通会话列表或独立继续；任务级取消与审批由GUI处理。模型/工具/工作区规则及额度见能力规范RUN-08，连接独立，不承诺OS隔离。
- 输入区发送按钮左侧环形显示当前上下文占用；点击或悬停600ms打开Popover，区分当前上下文与本会话累计，60%/80%分别切换警告/危险色。`/compact [可选提示词]`提交后直接压缩，浮窗按钮无提示词立即压缩且保留草稿，运行中禁用再次触发；压缩后未知用量等待后续响应更新。压缩启动后消费命令，消息区以单行显示过程及结果并可取消，成功摘要可展开。
- 模型认证、设置、上下文压缩、文件引用、直接 Shell 输入及原生输出操作均纳入基础范围；细节以能力规范为准。

### 3.5 内嵌能力（末语工坊方向，后续）

- 编辑器 Agent 经编辑器服务接口调用，不直接读写磁盘文件（D-08）。
- 工具分组：只读上下文（场景树、选中对象、资源索引、校验结果）、写入操作（增删节点、改属性、绑定资源）、交互能力（选择对象、确认批量修改）、辅助能力（预览、校验）。
- 安全：受控资源加载、工具面仅编辑器 API、凭据隔离；不承诺 OS 级沙箱（D-20）。
- 当前**只作为设计约束参与公共库设计**（D-17），不写编辑器代码。

## 5. 编辑器边界（末语工坊）

以下约束来自草案 §7.2 与对末语工坊现状的核实（React 19 + Zustand + Zundo，写操作经 store actions，未保存状态是常态）：

1. 编辑器 Agent 不提供通用 `bash`、任意路径 `read`/`write`/`edit`；如确需文本能力，提供受控专用 API。
2. 资源上下文支持未写盘状态，不以磁盘文件为唯一数据源。
3. 工具执行经编辑器服务接口（业务层/store actions），不绕过既有校验、通知与 Undo/Redo。
4. 自定义 Tool 卡片必须有通用回退展示，历史会话不因组件缺失不可读。
5. 编辑器主线程不被 Agent 长任务阻塞；异步工具考虑 UI 生命周期。
6. 资源加载策略受控：不把用户通用 Pi Extension 目录的任意代码引入受限 Agent。
7. 命名注意：末语工坊调试流程已有 checkpoint（marker 映射）概念；huan 的文件快照一律以「快照 / FileSnapshot」措辞，文档与代码中避免混淆。

## 6. 非功能需求

- **性能**：流式更新不阻塞输入；大文件查看不卡 UI；长列表按实测需要采用虚拟滚动等优化。
- **安全**：通用应用以用户进程权限运行并显式呈现敏感操作；编辑器 Agent 按 D-20 威胁模型设计。
- **可用性**：常用操作有键盘路径；文案经 i18n 库书写（中文为源语言，D-22/D-25）。
- **可维护性**：文档与规范驱动开发；迭代文档记录每次设计与实际实现。
