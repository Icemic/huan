# 多项目工作区与工作区级会话

- 日期：2026-10-31

- 关联能力：ENV-02、ENV-03、SES-01、SES-02、RUN-03、RUN-06、RES-01
- 依据：用户确认；[G1.2 阶段设计](2026-10-31-feat-project-session-branches.md)；Pi SDK 1.4.0

## 1. 目标与范围

将会话从单项目归属调整为工作区归属。一个工作区包含一个或多个项目目录；项目可以同时加入多个工作区，一个会话归属一个工作区。单项目工作区使用同一模型。

左侧按工作区一级、会话二级组织，提供工作区管理和成员动态增删。会话可跨成员目录读写、搜索和执行命令。文件树、Monaco、Diff 与文件快照继续沿用既有增强范围。

本设计替代 G1.2 阶段设计中“项目目录直接决定会话列表”的假设，保留 G1.2a 已实现的路径校验、信任和多会话生命周期基础。实现前先验证公开 SDK 与 pi-workspaces 工具适配，再完成存储、协议和 UI。

## 2. 已确认的产品决策

### 2.1 工作区、项目与会话

- 工作区具有稳定 ID、可修改的显示名称和非空项目集合；成员包含工具路径使用的别名与服务端文件系统的绝对路径。
- 会话显式记录 workspaceId；工作区改名、项目增删不改变会话归属。不能按 cwd 推断工作区，也不能因同一个项目属于多个工作区而重复归类会话。
- 新建会话默认使用该窗口在工作区上次选择的成员作为起始目录，首次没有记录时用界面首个可用成员；用户可改选。项目顺序仅用于展示和默认选择，不代表主项目。
- 会话创建后 cwd 固定。普通相对路径、默认 Shell、Pi 项目资源装配仍以它为基准；跨项目使用 @别名/路径 或明确的 Shell cwd。
- 成员移除只解除工作区关系，不删除目录、会话或历史上下文。若移除会话起始目录，它仍作为该会话的运行锚点显示，不会切换 cwd；路径失效时明确提示，不静默改到另一个项目。

### 2.2 动态成员与运行边界

工作区定义修改持久化后，关联会话采用新的成员集合。正在进行的一轮运行保持原来的根映射，结束后、下一轮开始前应用更新；steer、follow-up、工具回调、自动重试等在同一运行生命周期内保持一致，不能按单次模型响应更新。

会话运行时在内存记录已应用的工作区 revision，下一次运行准入时取得一致的成员快照。空闲会话可立即显示待生效变更；多窗口显示服务端返回的权威定义和实际生效版本。新成员的项目规则在相关操作前提供给模型，成员移除不会抹去模型已经见过的历史内容。

运行边界沿用现有 admission 与 agent_settled 结算机制；首次验证须覆盖已排队消息和扩展延迟动作，不能仅在浏览器发送按钮中更新状态。

### 2.3 项目资源与信任

工作区成员表示工具导航范围，不构成 OS 沙箱。加入工作区不代表许可执行其扩展，移除也不撤销已执行代码或进程文件权限。

每个会话只从其起始目录装配项目 settings、扩展和 MCP，沿用 G1.2a 的路径信任流程。其余成员提供目录映射与项目指令，不会合并多个项目的模型、扩展或 MCP 配置。用户级资源保持原有作用域。

项目指令按路径标明适用范围，在模型操作该项目之前提供；不把某个项目的 AGENTS.md 默认用作其他项目的规则。具体指令发现复用 SDK 已有语义并通过测试核对。

## 3. UI

左侧为可折叠工作区列表，工作区下仅展示会话。工作区行提供管理与新建会话；会话操作保留改名、归档和删除。展开状态、选中会话、草稿与新建起始目录偏好属于窗口状态。

当前会话上方展示所属工作区、项目数量和起始目录，提供“管理项目”。管理使用简单弹窗或侧栏，包含工作区名称、成员别名/路径、添加/移除、路径健康与资源信任信息。成员路径缺失时保留记录并提示修复，也不删除工作区。

工作区定义变更需要同步到其他窗口；浏览工作区或切换会话不停止任何运行。工作区下的会话列表按 workspaceId 查询，并跨 cwd 分组目录聚合，不能继续只过滤 header.cwd。

## 4. 存储与协议

### 4.1 位置与权威来源

huan 元数据使用单个版本化 JSON 文件 `<agentDir>/huan/state.json`，默认是 `~/.pi/agent/huan/state.json`。agentDir 由服务端显式参数或既有 Pi 目录规则解析；指定其他用户空间时，元数据随之隔离。首期不引入数据库，不默认向项目目录写文件。

```text
<agentDir>/
├─ auth.json              # Pi 认证
├─ settings.json          # Pi 配置
├─ trust.json             # Pi 路径信任
├─ sessions/              # 默认 Pi JSONL 存储，可被 sessionDir 覆盖
└─ huan/
   └─ state.json          # huan 工作区与会话附加信息
```

| 数据 | 权威位置与读取方式 |
| --- | --- |
| 工作区稳定 ID、名称、成员、revision | state.json；名称支持中文，项目别名与显示名称分开 |
| 会话的工作区归属 | state.json；按会话存储作用域和 sessionId 定位 |
| 会话归档、树当前节点 | 后续 G1.2b/c 在同一会话元数据中扩展 |
| 消息、名称、cwd、模型与会话树 | Pi JSONL；不在 state.json 重复维护 |
| 信任决定 | Pi trust.json；加入成员不写信任决定 |
| 目录健康、最近活动、token/费用 | 读取文件系统或 Pi 会话计算，不持久化副本 |
| 当前运行已应用的 revision、成员快照 | 服务端内存；重启后的新运行直接读取最新定义 |
| 展开、选中会话、新建起始项目偏好、可恢复草稿 | 窗口本地状态；需保存的部分用 sessionStorage，按服务地址/用户空间/会话作用域区分 |

工作区是 huan 自主管理的产品数据，不要求兼容 pi-workspaces 的 JSON schema，不引用其定义文件。上游格式导入导出、外部修改监听和 Pi TUI 双向同步均不在本轮范围内。

### 4.2 文件结构与会话作用域

以下为初始格式示例，ID 均为示意值：

```json
{
  "version": 1,
  "workspaces": {
    "ws_8f31": {
      "name": "幻开发",
      "revision": 3,
      "projects": [
        { "alias": "harness", "path": "/projects/harness" },
        { "alias": "editor", "path": "/projects/editor" }
      ]
    }
  },
  "sessionMetadata": {
    "store_a12": {
      "pi-session-id": { "workspaceId": "ws_8f31" }
    }
  }
}
```

- version 是文件格式版本；工作区 ID 独立生成，保持不可变。name 是可修改的中文显示名称，不再嵌套上游 definition 或维护第二个上游名称。
- projects 是非空有序数组，顺序用于展示；alias 在工作区内唯一，用于 @别名/路径，具体别名语法随路径解析验证固定。path 由服务端路径校验后保存为绝对路径。不存在另一个全局项目数据库，同一目录可以出现在不同工作区。
- revision 在工作区成功修改时递增；整个文件写入仍串行处理，不因不同工作区有各自 revision 而允许并发覆盖文件。
- store 标识由规范化的会话存储根路径确定。默认使用 `<agentDir>/sessions`，显式覆盖使用实际解析出的平铺 sessionDir；不按每个 cwd 分组目录生成 store。以确定性路径摘要生成标识，重启相同目录得到相同标识，避免切换 sessionDir 后相同 sessionId 错用归属或归档。

sessionDir 优先级、默认按 cwd 分组和显式平铺保持不变。元数据位置固定在 agentDir 下，按 store 分开会话关联；工作区定义在同一 agentDir 内共用。共享 sessionDir 不会共享不同 agentDir 的 huan 元数据，改变存储根也不会迁移关联。

已有无关联的 Pi 会话允许在 GUI 明确选择归属或以单项目工作区接入；不猜测多工作区归属，不批量改写个人 JSONL。具体入口在会话列表实施时确定，开发阶段不建设通用迁移框架。

### 4.3 写入、并发与失败

1. Node 服务端是唯一写入方，浏览器通过 API 修改。首期同一 agentDir 的 huan 元数据由单个服务端进程管理，支持多个浏览器窗口；不承诺多个服务端进程并发写同一文件。原子替换不能代替跨进程写入协调。
2. 所有元数据修改经过同一个串行写入队列，基于最新状态生成新文件；先写同目录临时文件，再原子替换 state.json。成功持久化后才提交内存状态和向页面报告成功，不在流式 token 事件中写盘。
3. 工作区修改携带预期 revision；过期请求返回冲突和重读提示。磁盘写入失败保留原内存和文件，页面显示失败；不会先广播成功再尝试保存。
4. 文件不存在才初始化为空状态。解析错误、未知格式版本或读取失败明确报错并保留原文件，不当成空状态覆盖；Pi 冷历史仍可只读查看，依赖工作区元数据的修改暂停。
5. Pi 会话文件与 huan 元数据没有跨文件事务。新建按“Pi 创建成功 → 保存归属 → 返回成功”处理；保存归属失败不伪报新建成功，若留下 Pi 文件，则作为未归属会话可被发现和接入，不会猜测所属工作区。

### 4.4 接口方向

protocol 区分 workspaceId、项目 path 和 session cwd；现有 workspacePath 字段实际表示 cwd，需按实际含义调整，禁止直接改成多根含义。新增工作区列表/创建/修改、成员操作和会话归属查询；前端与 HTTP 客户端同步调整，破坏性协议变更递增协议版本。

工作区修改遵循 §4.3；按需增加轻量的工作区变更通知或重查机制，不把整份定义附到每个 token 事件。冷列表/历史仍不执行项目扩展、不发模型请求。

## 5. pi-workspaces 复用评估

调研来源：[上游仓库](https://github.com/zhang-stephen/pi-workspaces)，commit `3d97e7acfafd92e737907a5453c16013a9f9dc1f`，package.json 版本 0.1.2，MIT。已阅读 README_zh.md、index.ts、workspace-store.ts、path-resolver.ts、tools.ts 与 prompt-inject.ts；尚未运行上游代码或证明其与 Pi 1.4.0 兼容。

已确认采用“参考设计、选择性复用源码、集成为 huan 内置能力”的方式。不直接安装/加载整个 pi-workspaces 插件，也不从零重写已适用的路径与工具机制；用户不需要安装该插件。

| 上游部分 | huan 处理方式 |
| --- | --- |
| @根别名/路径 解析 | 审查后选择性复用，验证当前平台路径行为 |
| 文件工具委托与 bash cwd | 复用必要源码和思路，以 Pi 1.4.0 测试为准 |
| 工作区提示词与项目规则 | 参考设计，调整到模型操作相关项目之前提供 |
| 定义存储与校验、会话关联、成员变更生命周期 | huan 自行实现，采用 §4 的数据结构和写入规则 |
| 自动激活、按名称日志恢复、TUI 命令/状态栏/补全 | 不接入，使用显式会话归属与 GUI |

工具和提示词仍通过公开 Pi SDK 的内嵌扩展工厂装配，实例按会话隔离；这是 SDK 接入机制，不代表加载上游完整插件或依赖它管理工作区。

必须核对的差异：

1. 上游使用全局 getAgentDir() 与安装位置判断作用域；不沿用这部分发现/存储逻辑，huan 显式使用所选 agentDir，不能读取或写入另一用户空间。
2. 上游以名称写 pi-workspaces:active 自定义条目；huan 的固定工作区归属以 sidecar 为准，不能与插件自动激活形成双重权威或重复注册工具。
3. 上游在工具执行结果后补首次触达规则，需提前到模型操作前；显式 bash cwd 已知有 PI_* 环境变量差异，需用当前 SDK 验证并处理。
4. 上游开发依赖基准 0.85.1；文件工具、Shell、取消、扩展 reload 和类型定义均以本仓库 1.4.0 验证。

采用必要的最小源码复用时保留 MIT 许可和来源、固定上游 commit、记录本地差异；不维护无关 TUI 代码。依赖安装继续遵守 minimumReleaseAge，不修改个人全局插件。

## 6. 验证与回退

自动化使用临时用户空间、确定性模型与临时多项目目录：

| 方面 | 验收 |
| --- | --- |

- 临时隔离空间与合成模型验证，无个人凭据/会话变更或付费模型请求。没有进行截图视觉审阅。

### 8.4 已知限制（不阻塞本轮范围）

- 空状态启动时提供稳定 ID 的单项目默认工作区草稿，首次成功写入元数据时一并保存；已有无元数据会话保持未归属。其他定义修改仍遵守先持久化再提交内存。
- 工作区删除按设计不在本期；GUI 不提供空操作按钮。
- 损坏 `state.json` 的冷历史与修改禁用已有服务端测试和 GUI 横幅；由于 e2e 服务端只在启动时加载存储，未用运行中外部改写文件制造该 GUI 场景。
- 外部直接修改 state.json 不会热加载，仍以服务端内存状态为权威；不在本轮外部同步范围。
- pi-workspaces 冲突按已加载扩展路径段识别，不检查未启用或未加载的插件包。
- 成员路径健康与信任信息在管理弹层打开/失焦时查询；其他窗口通过聚焦或显式刷新获取新定义。
