## 3. 用户空间与会话目录

### 3.1 用户空间规则

- `HarnessHostOptions.agentDir` 显式值优先；否则使用 Pi 的 `getAgentDir()`，自然读取 `PI_CODING_AGENT_DIR`，缺省为 `~/.pi/agent`。
- 宿主创建时将 agentDir 解析为绝对路径并固定；`~` 展开、相对路径基准及空值处理统一，不在各模块分别处理。
- auth、models、models-store、settings、资源和默认 sessions 均使用同一 agentDir。显式目录表示用户配置与默认数据位置选择，不承诺 OS 隔离。
- 项目 `.pi`、祖先指令及 `~/.agents/skills` 等 Pi 标准发现规则仍有效。自定义 agentDir 不应在生产环境悄悄禁用这些原生资源；自动化测试另做隔离。
- 不在宿主运行中改写 process.env 来切换目录；多个不同用户空间的宿主可在同一进程同时存在。

### 3.2 sessionDir 优先级与含义

建议增加宿主 `sessionDir?: string`，对应 CLI 的显式 `--session-dir` 优先级；应用沿用 `PI_CODING_AGENT_SESSION_DIR`，不新增同义环境变量。

| 优先级 | 来源 | 存储形态 |
| --- | --- | --- |
| 1 | 宿主显式 sessionDir | 指定的会话目录本身，平铺；不再追加 cwd 编码 |
| 2 | `PI_CODING_AGENT_SESSION_DIR` | 同上 |
| 3 | 启动工作区合并后的 `sessionDir` setting | 同上，项目 setting 优先于用户 setting |
| 4 | 默认 | `<agentDir>/sessions/<Pi 编码 cwd>/` |

遵循 CLI：会话目录 setting 在项目信任前用于发现；只读取这一必要设置不等于授权项目扩展。宿主本次的显式/env/setting 目录覆盖在启动时固定；无覆盖时每个目标 cwd 使用自己的默认分组。未来 GUI 项目选择若需按新项目重新选择存储作用域，在 G1.2 明确执行边界，不让已有会话随配置变动自动换目录。

路径规则：显式/env 相对路径以宿主启动进程 cwd 解析；setting 按 Pi 文档以宿主启动工作区解析。需要显式记录该基准，并针对相对路径测试，因为现有 `getSessionDir()` 仅做路径标准化，不能直接假定已按目标 cwd 解析。

### 3.3 默认目录兼容与查找作用域

Pi 1.1.0/1.4.0 当前默认目录算法：展开并解析 cwd，移除开头的一个路径分隔符，将 `/`、`\\`、`:` 换成 `-`，加上两侧 `--`，置于 `<agentDir>/sessions/` 下。目录名用于兼容存储，不能反向推导 cwd；cwd 以 session header 为准。

由于辅助函数未从包根公开导出，建议在 core 的单一小模块中维护这项必要兼容逻辑，注释标明 Pi 来源与基准版本，并以临时 HOME 的子进程对照 SDK 默认结果。生产代码不深导入 SDK 内部子路径、不创建个人默认目录来探测名字、不对整进程临时改环境变量。若升级后发现公开替代接口，优先使用公开接口。

| 操作 | 统一行为 |
| --- | --- |
| 创建、列表、continue、按 ID 查找 | 所有 SessionManager 调用显式传解析后的目录；默认分组与平铺覆盖都按 header cwd 过滤当前项目 |
| 默认空间跨 cwd 查找 | 只枚举当前 agentDir 下 sessions 的直接分组目录，通过公开 SDK 列表方法读取；不调用无参数 listAll 回到全局默认空间 |
| 显式目录跨 cwd 查找 | `SessionManager.listAll(explicitDir)` 读取该平铺目录；不把它当默认 sessions 根递归扫描 |
| 打开、改名、删除 | 仅使用当前作用域发现的文件；打开时保留相同存储规则；ID 冲突需报歧义，不用 Map 静默覆盖路径 |
| 自定义目录不存在 / 不可写 | 列表可为空；创建失败显示对应目录错误，不回退到用户默认空间 |

目录枚举维持 O(n)，使用现有缓存并避免逐 ID 重扫。默认根下的符号链接不作为另一个空间的隐式入口；路径规范化及边界判断需覆盖 Windows 盘符、大小写和符号链接。显式选择的外部目录可以共享，GUI 必须标明这是用户主动覆盖而非完整隔离。

本次不迁移、拷贝或清理已有用户数据。fork/clone/import 尚未实现，只要求后续通过该统一存储规则接入，不在本次新增空接口。

## 4. 测试隔离与升级验证

### 4.1 默认自动化

采用真实 SDK + 本地合成 provider + 确定性响应，不把宿主集成测试整体改成 mock host：

- 每组用例创建临时 agentDir、workspace、sessions，写入合成 provider、虚假测试 key、最少设置，覆盖两个测试模型与缺凭据模型。
- 当前直接创建探针 SessionManager 的测试也显式传测试会话目录，清理只触及临时根；初始化失败时 cleanup 可安全执行。
- 测试启动前清除/覆盖 PI_PROVIDER、PI_MODEL_ID、PI_CODING_AGENT_DIR、PI_CODING_AGENT_SESSION_DIR 等影响结果的继承值，测试结束恢复；不修改实际用户文件。
- 默认禁止非预期网络请求：目录不联网刷新；模型使用确定性流；所有 fetch mock 均在 finally 恢复。真实环境兼容测试单独显式运行，不靠凭据缺失时跳过全部默认测试。
- 自定义 agentDir 不能隔离全局 Agent Skills 与祖先上下文。建议开放 SDK 原有 `resourceLoaderOptions` 的受约束透传，使测试关闭 Skills/模板/主题/上下文发现，同时保留临时目录内的测试扩展；不要增加 testMode 分支。宿主输入守卫工厂始终由宿主追加，调用者不能替换它。

涉及 getAgentDir 默认路径、HOME 与 cwd 的断言使用独立子进程和临时 HOME/USERPROFILE，避免 SDK 提前导入和 Vitest worker 共享环境导致个人资源被读取。测试生命周期或设置必须先于被测 SDK 初始化。

真实用户环境验证只做显式选择的兼容检查，默认不发送付费请求、不删除真实会话；确需验证写入时必须另行确认并限定临时工作区。

### 4.2 升级顺序

1. 先以 1.1.0 实现目录一致性和确定性测试，记录可复现结果，不拿当前个人配置失败当升级回归。
2. 经确认后统一升到 1.4.0；检查实际 Pi 内部依赖版本，跑全量类型、宿主竞态、事件回放、SSE 验证。
3. 特别检查预检取消、扩展 triggerTurn、session_shutdown 延迟动作及消息隔离；确认是 SDK 语义变化还是宿主缺陷，再调整实现。
4. 完成重连与状态呈现后跑最终 check/build；记录仍需平台或真实环境验证的内容。

不要求阶段中间每次编辑均保持全量通过，但不得在最终结果中隐藏与升级相关的失败。

## 5. 重连设计

问题出在 Controller 创建新 transport subscription 时依赖 loadState 决定是否要快照；同一 SSE connection 内重试已经会请求恢复快照，不能只修 HTTP 客户端。

设计：在 `ensureEventSubscription` 创建新订阅时统一要求 `includeSnapshot: true`。所有入口（显式 connect、发送触发订阅、dispose 后再次订阅）遵守同一规则，不只改 connect 的调用参数。

保留单连接复用、30 秒无消费者宽限期、generation 迟到事件拦截及现有 seq 重置处理；重复 connect 不重新建连接。快照与增量仍由宿主同一个订阅边界交付，不增加“先 GET、再 SSE”的间隙。

必须检查新快照与正在发送的乐观消息、乐观队列、迟到 HTTP load 的竞态：不覆盖新事件、不重复消息、不撤销新输入。上游移植测试中“已加载后跳过首帧快照”的断言应按新契约修改，并增加行为测试，不只是反转布尔断言。

## 6. GUI 状态与默认模型错误

### 6.1 只读状态入口

建议在协议客户端增加 `getHostInfo()`，由 core 提供、HTTP 客户端传输；应用增加经过现有 Host/Origin/token 校验的 `GET /api/pi/host`。健康检查继续只返回 ok，不携带路径或诊断。

只返回 JSON-safe 的当前 workspace、解析后的 agentDir、存储模式/路径/来源、默认模型就绪状态与经过筛选的诊断；不返回 settings 全文、环境变量全集、auth 内容或模型请求密钥。配置启动时固定，GUI 不提供热切换用户空间，说明手工指定和重启方式。

GUI 在空白会话和启动失败提示区域也能显示此信息，不依赖先创建一个会话。提供复制诊断摘要、重试状态请求、选择已有模型入口。网络不可达、目录不可用与模型未配置应分别提示；重试请求不冒充 reload。

### 6.2 恢复规则

| 情况 | 行为 |
| --- | --- |
| 默认模型不存在 | 宿主仍启动，列表与历史可读；状态显示来源、无效选择及修复方式；新建未指定模型则返回明确错误，不创建假会话、不静默换模型 |
| 用户在空白页显式选择有效模型 | 使用现有模型草稿随 createThread 传入，覆盖无效默认；无需修改 settings 或先回 TUI |
| 模型存在但无凭据 | 显示 missing-credentials，运行前失败且不误报成功；登录入口属于 G1.4，本次说明配置文件/环境变量与重启路径 |
| 冷打开旧会话的模型不可用 | 继续由 SDK 恢复/回退，并将原因可见；不让无效全局默认阻断与它无关的历史读取 |
| 目录或服务发生非模型故障 | 保留错误，不用笼统 catch 吞掉或转成 missing-model；宿主无法启动时 GUI 显示连接/启动诊断建议 |

现有 PI_PROVIDER / PI_MODEL_ID 按字段与 settings 合并是已存在行为；本次不顺便改成新优先级。状态须显示最终选择及各字段来源；测试清理继承值避免组合出无关模型。若后续要改成成对覆盖，需单独讨论行为变更。

默认解析失败不再使整个 createHarnessHost 拒绝，但显式 createThread.model 不存在仍拒绝。实现时以结构化模型解析结果区分有效、未配置、选择无效与缺凭据；不以匹配异常文案判断状态。

## 9. 风险、回退与编码前确认

- SDK 升级涉及已有取消语义。建议升级到 1.4.0，但必须先建立可重复基线并保留专门回归；不把全局安装版本当项目依赖。
