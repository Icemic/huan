# 子agent三模式调用修复

## 1. 目标与范围

保留Pi示例的single、parallel、chain接口，修正huan模式判断偏差，减少模型重复调用失败。单次并行最多8项、同时4项，链式传递、审批、取消、子记录与用量展示沿用既有行为。无需协议变更或数据迁移。

## 2. 设计

模式按有效内容选择：非空tasks数组为parallel，非空chain数组为chain，agent与task均为非空字符串才构成single。空数组、空字符串不构成模式。只有一个有效模式时执行；没有有效模式时指出必填字段；多个有效模式时列出冲突字段，给出单个、并行、链式正确参数示例。部分single字段在没有有效模式时准确报缺失，不将空占位算冲突。有效的多个模式仍拒绝，不能猜测选择。

模型可见的工具说明明确三种参数形状、互斥规则以及不存在mode字段，示例使用agent占位名并提示替换为可用定义。参数描述也注明其他模式应省略。通过SDK公开before_agent_start钩子在每轮请求系统提示中加入用户agent名称与职责，只读所选agentDir的用户定义，不为目录提示读取项目定义正文。每次调用仍重新按agentScope发现和校验定义；项目来源继续遵守既有作用域与审批规则。无定义时明确提示，定义读取失败不阻止主会话普通对话，调用时继续报告具体错误。

不新增模式参数、工具或兼容层，不修改Pi SDK和个人扩展。

## 3. 验证与回退

单测覆盖single附带空数组、parallel/chain附带空single占位、两种非空数组冲突、缺少agent或task、全空参数、提示中的用户定义名称/职责与每轮更新。使用完整SDK服务调用检查模型参数进入工具后的行为，并保留既有并发/链式/审批测试。主agent独立review及定向测试、core类型、代码和文档检查完成后本地提交，不push。

回退撤回此次工具判定和提示变更，既有子记录与协议不受影响。

## 4. 实施与验证

主agent独立review后移除测试中间接解析pi-ai依赖的辅助代码，改为既有服务集成测试覆盖SDK校验过程；链式与并行请求添加空占位，父模型请求检查用户agent名称和职责出现、正文保持子会话独有。单测覆盖single空数组、批量空字符串、有效冲突、缺字段、定义目录每轮更新、项目定义不注入及失败不阻塞主对话。

主agent亲验4文件26项测试、core类型与1条Chromium通过。浏览器单任务携带tasks与chain空数组，执行审批、实时速度和刷新重开流程。使用隔离agentDir与合成provider，8898/8899、单worker、无retry。日志为系统临时目录huan-subagent-invocation-unit.log、huan-subagent-invocation-types.log、huan-subagent-invocation-e2e.log。未运行全仓测试/build，worker另执行的411项测试不计为主agent验证。

模式和schema保持原接口，协议19不变；未修改个人配置、扩展或SDK。
