# 子agent中断后的卡片恢复

## 1. 目标

后端退出后重新打开父会话，保留subagent专有卡片。已完成任务保持终态；服务不再持有的running/waiting任务显示cancelled，提示服务已停止，清除待答计数，运行统计结束。读取恢复不重新执行任务，不改写Pi聊天记录。

## 2. 原因与设计

最新测试会话01a1a98f-4ea1-7331-92aa-22b0335de6b1包含一个并行subagent调用，父记录缺少最终toolResult；两个task.json分别为completed和running。临时进度只存在内存，重启后details缺失导致专有卡片丢失；展示层对缺结果工具默认running。

由SubagentSessions按父会话ID、持久toolCallId及当前投影中的subagent调用读取摘要，仅恢复当前分支且尚无最终工具结果的调用。通过既有toolExecutions及partialResult.details形状补入快照。冷快照和重新打开后的热快照使用同一恢复逻辑；活动工具优先，避免覆盖当前运行。最终结果已存在时沿用最终结果。任务详情与卡片共用服务失去任务后的终态规则。

只读取指定父记录的任务目录，按调用ID分组，一次扫描；不全空间扫描、不新增后台恢复任务。没有任务摘要时保留现有错误边界；文件损坏明确报错。链式模式由原调用参数决定。并行已完成项保留结果和用量，其余转停止。无需协议升级或迁移。

## 3. 验证

覆盖completed/running/waiting混合摘要、同父多个调用及分支隔离、已有最终结果与当前运行不被覆盖、详情无待答、冷/热快照一致。SDK集成使用隔离记录构造退出后的保存状态，再创建新服务验证恢复；浏览器验证专有卡片、终态与打开详情。保持8898/8899隔离服务，日常8799/8788只读检查。

完成后主agent独立review、亲自验证、更新文档并本地提交，不push。回退撤回快照恢复，原始会话与子记录保持。

## 4. 实施与验证

SubagentSessions恢复父工具details，SessionCatalog与SessionEvents统一调用。当前服务持有的未结束任务使用实时进度，恢复项不覆盖活动工具；父调用因缺少最终结果显示error，子卡各自保留completed或cancelled。冷任务详情和父卡共用终态及待答清理。工具执行快照字段保持既有形状，协议19保持；协议注释同步其展示恢复用途。

主agent独立review并直接修正父工具结局、存活任务排除与详情清理，亲验3文件33项测试、全仓类型及1条Chromium通过。浏览器用隔离保存记录模拟服务退出后的一项完成、一项运行、一项排队，检查专有卡片、终态、无取消按钮及待答、详情聊天和刷新。截图interrupted-subagents.png已实际读取，卡片保持、完成和已取消清晰可见。此次以退出后保存状态验证，未实际杀进程；日常8799/8788只读检查，未改写用户会话。
