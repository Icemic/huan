# 本轮运行速度统计

## 1. 目标与范围

主agent与子agent统一统计最近一次完整运行：agent_start到agent_settled，覆盖多次模型调用、思考、工具执行与等待。输出token来自本次运行自身助手消息的usage.output，主agent不重复计入子agent用量。主会话放上下文用量浮层；子任务放现有用量摘要与详情。

PTY按用户决定暂缓。本次保持上下文浮层600ms悬停、w-60 gap-2 p-2及现有主题。无需新增依赖或基础UI组件。

## 2. 计算规则

平均速度为本次输出tokens乘1000除以总耗时毫秒。单调时钟计时，排队与装配发生在agent_start之前，计时从实际启动开始。首响应耗时为启动至首次收到非空思考、正文或工具调用内容的时间。输出优先使用流式usage，响应结束以message_end的服务商用量为准，不用字符估算。

重试及自动继续仍属于同一运行，agent_end不能提前结算；最后agent_settled才冻结耗时。新的完整运行重置数据。子任务再次启动时使用最后一轮。失败与取消保留已报告用量和实际耗时，明确状态。没有正输出用量或有效耗时显示占位，不推测历史时间。

运行中每500ms显示截至当前的输出、平均速度、已用时间与首响应；工具等待期间继续计时。优先读取流式usage累计快照，每个message_end替换为最终用量，避免重复加计。服务商尚未报告用量时显示等待用量，已有时间与首响应照常显示。子卡片运行中同时显示速度、时间与首响应。结算后冻结最终值，浏览器不独立计时。

## 3. 数据与保存

主会话最终统计保存到会话旁的`<sessionFile>.huan-metrics.json`，以结束时Pi节点ID为键；通过当前分支倒序读取最近统计，随会话删除。文件原子替换，单个SessionManager缓存读入结果，切换会话文件后失效；失败记录诊断，内存统计继续可见。子任务复用task.json与父工具摘要。浏览器通过run_metrics事件及metadata快照读取权威结果，不独立计时。

分支切换以目标分支节点为准，缺少统计文件的历史显示未知；单独导入或分叉生成的新会话文件不复制旧统计。协议升级为19，跨包边界与wire校验同步维护。SDK重试可能再次发送agent_start，已运行中的采集器保持本轮起点与累计量，agent_settled后下一次启动才重置。

## 4. 验证与回退

单测使用可控时钟验证多次模型调用及工具等待、主子隔离、重试延续、新运行重置、首响应、取消与未知用量。覆盖协议归约/校验、持久重开及子任务摘要传递。隔离Chromium核对浮层和子卡片/详情实际显示，读取截图；定向类型、文案提取、代码及文档检查完成后本地提交，不push。

回退通过撤回本次代码；统计文件独立于Pi消息记录，旧会话仍可读取。

用户指出最初仅结算后展示无法满足任务中观察数据的场景。主agent已直接修改：服务端每500ms推送当前耗时与用量，流式usage按响应累计值替换，结束时才加进本轮完成量；首响应、输出与已用时间不再被统计中占位隐藏。主子统一，工具等待期间分母继续增长，结束和释放会话时清除计时器。

修订后4文件58项单测、全仓类型与1条隔离Chromium通过。浏览器停在子任务待确认阶段，验证主子速度可见、服务端耗时持续增长、首响应可见，再确认结束与刷新保留。已读取run-metrics-running.png与完成截图，新增可控时钟测试核对流式快照不重复累计及结束后停止推送。日志为huan-run-live-unit.log、huan-run-live-types.log和huan-run-live-e2e.log。
