# 整体整改：实施决策调整记录

日期：2026-11-02。本文只记录实施时的小范围决定，步骤状态仍由[子路线图](../../architecture-remediation-roadmap.md)维护。较大偏差或难以判断的取舍须停下询问用户。

## 授权

用户已确认精简后的R2，授权连续实施R3～R9，包括必要的生产代码、依赖、正式测试及隔离验证。每阶段由主agent规划，`local/deepseek-v4.1-flash:max`实施，主agent独立review、亲自修正和验证后提交，再进入下一阶段。中途允许不可用WIP；最终合并和push未授权。

## 决定

### D-01：R3基础与应用接入分包

R3a先删除公共Controller/aui运行时并实现Zustand基础，R3b接应用实例与目录，R4接提交业务。旧消费者允许报错，不加兼容导出。原Controller业务测试按`9bcf157:packages/react/src/runtime/thread-controller.test.ts`追踪；发送/图片/取消/取回/结构等有效断言在R4/R8迁移，R3a的236项新测试通过不代表这些行为已验收。

### D-02：未启动取消只结束对应提交

核对`core/src/host.ts:3167`发现等待准入被取消也会发cancelledBeforeStart，可能同时存在另一运行。归约仅推进该事件水位，不改共享运行状态；发送结果由R4结束对应本窗提交。主agent纠正worker将此事件置idle的实现及测试。

### D-03：R3资源边界修正

主agent将目录版本表改为循环外复制，附件引用改为单次Set索引，避免二次复杂度。驱逐后目录刷新可更新运行字段；认证迟到读取不覆盖新订阅。终止性断流提供显式reconnectThread，仅恢复观察、不重发任务。
### D-04：模型范围原文

R6b确认core此前只返回解析后的ID，前端无法保留会话通配原文。原文在record内存保留，沿用现有scope.patterns返回；新打开取已应用默认，显式修改后更新；不新增持久化或扩展任意修改来源跟踪。主agent亲自修正并更新对应前端测试。

### D-05：R8测试与局部顺序调整

命令只按发起草稿版本消费，模型设置自身推进版本单独处理，不裁剪后来输入的同前缀文字。工作区保存按草稿内容决定是否自动关闭，另用面板代次防关闭重开。live首帧使等seq旧冷读取失效，目录不能丢会话模型回退原因。

生产性能预览每次按当前源码构建临时产物，专用Vite插件注入计数，默认产物/业务组件不带计数器。取消测试用实际启动gate及PID回收，不以900ms任务管理器耗时作为取消正确性。隔离目录复用Node原生有界删除重试；EBUSY锁持有者未证，AR-34仍未关闭。该判断属当时执行时点，AR-34 后续按 D-07 关闭。

### D-06：R9补充图片与模型证据

图片解码失败提供可读提示、替代文本和来源，关闭空预览入口；加载状态仅属组件UI状态。补充无消息JSONL导入用例，沿用SDK对空历史选择有效模型的规则。隔离测试默认模型从不存在改为已注册但缺凭据的合成provider，以验证登录后的同页就绪；注册表不存在模型的服务端测试继续保留。此改动只影响隔离fixture。

AR-34记录可确定部分和未确定部分。Node原生有界删除重试只改善测试清理，不能证明EBUSY原因；最终用户决定前维持总阻塞，不把R9记录完成写成整体整改完成。该结论属当时执行时点，后续决定见 D-07。

### D-07：AR-34 由用户决定关闭

用户选择把AR-34剩余现象按开发环境/系统问题处理，不作为软件本身问题，接受剩余不确定性，结束本次整改：`host-reload` 清理 EBUSY、默认 e2e 产物 500/trace 消失/Chromium 崩溃、Vite 旧转换空模块。`provider-auth` 偶发 false 已在此前定位并修正测试初始化配置，不属于本次接受的剩余疑点。

保留的事实：`host-reload` 清理 EBUSY 的具体锁持有者未确定；上述历史工具异常的原因均未确定；本轮没有新增原因证据，历史记录中的条件与判断继续有效。43 项 AR 全部关闭，R0～R9 开发整改完成；合并与 push 未授权，等待用户单独确认，G1.5 未启动。

D-05 与 D-06 中“AR-34 仍未关闭”与“维持总阻塞”的表述属各自执行时点，本决定生效后以本条为准。
