## 3. 保留、简化或不采纳的建议

### 3.1 保留必要保护

| 建议/对象 | 主agent决定与理由 |
| --- | --- |
| 简单会话lease、StrictMode同轮微任务释放、目录与完整缓存分开 | 保留。现有registry按访问累积且dispose保留可重用状态；引用计数和一次微任务比30秒宽限更直接。未确认当前泄漏，不能把Q类改为复现缺陷，也不预建LRU |
| query目标键/版本、draft/selection/panel版本 | 保留。现有模型目录跨目标复用、树/fork只比thread或直接切换，存在明确保护缺失；不是假设性分布式冲突系统 |
| Node准入、取消/退休、pending资源移交与MCP唯一manager | 保留实际语义。host体量只是定位线索，拆模块依据共享状态与生命周期，不按行数认定功能缺陷；不重写已有MCP/认证底层 |
| 一次协议同版比较、扩展JSON-safe边界和共用wire守卫 | 保留最小实现。协议常量目前没有实际比较，unknown扩展数据确会进入编码；仅局部转换与受控回退，不建设保真JS序列化或全字段schema体系 |
| AR-37～43展示/迟到/原因/快照 | 保留。图片和prefill存在明确数据丢失路径；子调用没有对应展示，带toolCallId请求被分入工具关联路径后可能没有可见入口；快照缺省与旧值问题按字段语义修正，无需新协议平台 |

子代理用`host.ts:5018`的listLive说明目录可发现性，主agent核对发现该入口属于MCP broker，并非会话列表。`host.ts:5694`的listThreads仍从磁盘infos出发，只叠加匹配的live元数据；合并尚未写文件的live条目仍是R2目标要求。不能用这条错误引用证明现状已满足，也不能因此恢复通用结果系统。

子代理将AR-09/17/19/20部分称为“缺陷”，主agent不照抄类别：registry和大闭包能证明结构现状，不能单独证明内存泄漏；版本策略和JSON-safe是应明确的边界，不能声称已有生产事故。子路线图A/Q状态保持。

### 3.2 AR-34不采用“环境项直接关闭”

子代理建议将历史异常拆为应用/测试项与工具/环境项，后者可按隔离记录关闭。主agent只接受避免无限排查的部分，不预先按症状分类。

独立outputDir通过、Chromium崩溃或Vite重启恢复，均不足以证明原因与应用无关。EBUSY也可能来自资源未释放，不能先称环境问题。R0已纠正该措辞。

R8在正常最终验证中记录首次失败，复现的产品/测试问题修复；历史未复现记录条件、证据与判断，不强求编造原因或不断增加重跑。仍影响验收或不能判断产品是否有问题时保持未解决，交用户决定。AR-34本轮未关闭，解除阻塞规则保持，无自动豁免。

### 3.3 不把简化变成功能删减

子代理提出恢复文本“用户可重做”、取消IME自动化等候选。主agent不以低概率或测试难为由丢弃已有输入/取回内容或取消中文输入要求。简化通用结果系统和测试排列后，原文恢复、同目标新草稿保护、IME不误发、断流和多窗行为仍须保留。

caller使用sessionStorage，复制标签页可能共享ID，是源码边界推断，尚未运行复现错误领取。本次不改caller策略、不加窗口选主；R1/R2明确不承诺跨刷新指令接管，也不把该组合新增为必须修复项。
