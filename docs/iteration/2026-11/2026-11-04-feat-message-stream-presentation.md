# 消息流展示调整

日期：2026-11-04

本文记录工具调用、subagent、上下文压缩和用户Shell的多轮展示设计与验证。计划及各轮状态由[roadmap §2.3](../../roadmap.md#23-当前阶段消息流展示调整随后-g15)维护。第一轮§5详细规格及静态稿已由用户确认并完成实施，执行证据见§7。

## 1. 目标与范围

提高消息流的可读性与视觉一致性，完整保留工具参数、输出、错误、图片和执行元数据。采用现有字体、主题、官方Base UI组件及紧凑布局；通过内容结构、对齐与留白建立层级。

第一轮覆盖read/write/edit/bash的专门展示、压缩字号和用户Shell样式。Subagent纳入后续轮次，本轮只记录设计依据，任务卡结构与字号保持，相关调整在下一轮统一设计。其任务卡、完整记录、取消和Host UI能力继续保留。每轮按讨论结论实施、review和验证，在本文追加记录。

涉及能力：RUN-04、RUN-08、MOD-04、RES-05及既有消息图片展示。能力定义以[Pi GUI能力规范](../../pi-gui-capabilities.md)为准。

## 2. 现状分析

| 位置 | 当前实现 | 影响 |
| --- | --- | --- |
| `chat/tool-part.tsx` | 基础工具共用参数JSON与文本输出块；标题按command/path/query截取80字符 | 写入内容含转义字符，edit缺少差异层级；路径与范围不易扫读 |
| `ui/trace.tsx` | TraceLine默认text-sm，图标16px | 已有一致的14px过程标题基础 |
| `chat/compaction-status.tsx` | 成功TraceLine、运行/失败/取消行及摘要单独使用text-xs | 压缩过程比工具和Thinking小；各状态的布局也有差别 |
| `chat/data-part.tsx` | Shell与摘要覆盖为12px，退出码等缩至11px；非零退出码没有独立错误样式 | 字号分散，执行失败不醒目 |
| `model/message-view.ts` / `chat/chat-message.tsx` | bashExecution以data部分进入助手侧消息 | 用户发起的Shell与Agent工具调用缺少位置区分 |

Shell实时输出目前位于运行面板，持久结果位于消息流；二者使用不同布局。Subagent任务卡目前为12px，模型名11px，嵌在工具折叠内，另有任务状态徽标与查看/取消按钮。

以上结论来自代码与样式审阅；本轮尚未运行界面或读取截图，不视为视觉验收。

## 3. 参考实现

核对本地锁定Pi 1.4.0的`dist/core/tools/renderers/{read,write,edit,bash}.js`：read以路径和行范围为标题，write直接展示内容，edit使用结果差异，bash以命令和输出组织内容并保留截断及完整输出路径。借鉴其按工具表达信息的方式，huan仍保留成功结果与所有可查内容。

核对[OpenCode固定版本工具展示](https://github.com/anomalyco/opencode/blob/8f5d19281015a3ac9156f4f33922823265eafb02/packages/session-ui/src/tools/tool-renderer.tsx)：read展示文件与读取参数，write使用文件内容视图，edit优先使用执行结果差异、缺失时使用替换片段，用户Shell复用Shell内容组件。其read会收起文本结果，huan保留展开后读取完整已收到结果的能力。

参考仅基于源码；没有运行这两个产品进行视觉对比。

## 4. 第一轮建议

### 4.1 基础工具

共用一行标题：类型图标、动作、主要对象、必要状态。路径与命令用等宽字体；标题在窄屏允许主要对象收缩，完整路径及完整命令在展开内容中可选择、可复制。取消标题中重复出现的“已运行”和右侧“完成”，保留运行、错误、等待交互等有用状态。

| 工具 | 收起时 | 展开时 |
| --- | --- | --- |
| read | 文件图标、读取、路径、显式offset/limit对应的读取范围 | 完整路径与范围，返回文本的代码视图或图片；保留截断与继续读取信息 |
| write | 文件图标、写入、路径、内容行数 | content直接作为代码展示并可复制；保留执行结果/错误，空内容也能明确识别 |
| edit | 修改图标、编辑、路径、替换段数 | 成功优先展示details.patch或details.diff；替换参数的每段oldText/newText可完整查看与复制；失败显示错误及尝试替换片段 |
| bash | 终端图标、命令摘要、运行/失败等状态 | 完整多行命令、显式timeout、完整已收到输出、图片、截断与完整输出路径 |

read范围依据调用参数，不将请求limit伪称为实际读取行数。write缺少写前文件快照，标题使用“写入”，不声称创建新文件或展示伪造的文件差异。edit运行中展示请求的替换片段，成功后以SDK结果表达实际修改；缺少patch时也不读取当前文件重建历史。

标准字段转换为专门的内容与元数据展示，不再显示对应的参数JSON。未知额外字段及未知details继续可查，扩展工具或形状不符时保留通用回退。已有图片、嵌套调用、部分输出和等待交互不因专门展示丢失。

成功默认收起，错误默认展开；用户手动选择的开关保持。展开后可滚动查看完整已接收内容，视觉截断不删除原文。服务端已截断的结果如实显示范围与完整输出路径，不宣称能恢复未传来的内容。

### 4.2 字号与压缩

过程标题、状态主文案、展开摘要统一14px，行高沿用现有消息与Trace。正文与代码14px，次要路径元数据12px；过程标题中的主要路径仍为14px。

TraceLine调用处的text-xs应移除，让其使用上游默认text-sm。压缩运行/取消/失败的普通行也要同步14px、16px图标、行高与间距；只移除成功行的className无法完成统一。成功摘要与分支摘要继承相同正文尺度。

压缩继续使用现有单一状态行和摘要展开，保留取消操作、错误、压缩前token及历史位置。普通终态不添加大面积背景，失败依靠现有destructive色及图标表达。

业务调用处调整字号，保留`components/ui/`上游默认结构；不全仓删除text-xs。

### 4.3 用户Shell

建议命令与结果作为一组右对齐，命令区域沿用用户消息的muted底色，终端图标与`!`/`!!`提示符保留。命令文字左对齐，用等宽字体；输出使用与Agent bash相同的代码展示，长输出可占更宽空间。来源依靠位置和表面样式表达，辅助技术仍提供明确名称。

展开区域保留完整命令、输出、退出码、取消结果、截断状态、完整输出路径和复制动作。`!!`附带一个低强调的上下文排除图标，Tooltip及可访问名称解释含义。非零退出码使用错误色，取消使用中性色，执行中显示统一运行状态。正文和折叠行14px，次要元数据12px。

在应用消息分派处识别`pi-bash-execution`，赋予用户Shell自己的展示组合；不把它改写成普通用户聊天文本，不增加fork等不适用动作，不改变Pi记录角色或模型上下文。

本轮建议先统一消息中的Shell历史与现有运行面板的终端内容样式。把实时Shell移入消息流还涉及运行记录与持久消息的可靠关联，应作为下一轮明确范围；当前持久消息没有run.id，不能按相同命令猜测同一次执行。

## 5. 第一轮详细视觉规格

本节将§4落实为实施规格。[静态设计稿](message-stream-round-1.html)支持明暗、窄屏及折叠切换。设计稿为独立文档示例，不作为应用基础组件来源；其中read展示默认收起，其余示例为便于比较而展开，实际默认规则以本节为准。没有列入本节的额外交互先由主agent讨论，不交给worker选型。

### 5.1 共用尺寸、布局和状态

| 项目 | 确定值 |
| --- | --- |
| 主文字 | 14px；过程行20px行高，展开正文/代码22px行高；动作文字400字重 |
| 次要文字 | 12px/18px；颜色muted-foreground，数字tabular-nums |
| 字体 | 文字font-sans；路径、命令、内容font-mono，沿用当前Geist/思源黑体/FiraCode配置 |
| 过程行 | 最小高28px；图标16px；图标、动作、对象、元数据间隔8px；末尾16px箭头 |
| 对齐 | 工具与压缩左对齐；内容接现有Trace竖线，左外边距7px，边线后内距16px |
| 展开间距 | 标题与内容8px，各内容区8px；连续工具过程行间隔4px，不给每个工具再套外框 |
| 内容块 | 现有CodeBlock默认size；1px input边框，4px圆角，无阴影；padding在调用处覆盖为标题横向8px、正文横向12px |
| 内容块标题 | 至少32px高，12px次要文字；路径允许换行，复制按钮靠右；正文上下8px/12px |
| 滚动 | 每个代码/输出区max-height:min(40vh,320px)，外层官方ScrollArea承担双向滚动；不切掉原文；内容区不叠加渐隐遮罩 |
| 操作 | 内容复制使用24px ghost图标按钮、14px图标；静止隐藏，hover/focus-within及触屏可见；Tooltip与可访问名称明确复制对象 |

标题严格排列为`图标 / 动作 / 对象 / 元数据 / 状态 / 箭头`。动作与状态不收缩，对象flex收缩并省略；元数据12px。工具标题以内容宽度为准，最大不超过消息列，不将完成标记推到消息列最右边。完整路径显示在展开后的内容块标题，可选择并附路径复制按钮；内容复制按钮放其右侧。

消息列可用宽度小于480px时，隐藏标题的范围/行数/替换段数元数据，它们在展开后原样可见；状态与箭头保留。主要对象可以缩到很短，但动作不省略。多行命令收起时只显示第一行，存在后续行时追加`…`，不把多行空白压成一行命令。

| 执行状态 | 标题及内容行为 |
| --- | --- |
| 参数到达/运行中 | 原类型图标替换成Loader2，状态“运行中”，沿用Trace运行效果；默认收起，可手动打开；已到达的内容持续显示 |
| 部分输出 | 输出块标题为“输出中”；不重复添加“以下为部分输出”等段落；完整结果替换临时输出 |
| 等待交互 | 恢复类型图标，状态“等待交互”使用现有amber主题色；不将整行降透明；Host UI入口保持原位 |
| 成功 | 类型图标、动作和对象，省略“完成”；对象foreground，动作和图标muted-foreground |
| 失败 | 类型图标、状态“失败”及动作使用destructive；路径仍foreground；默认展开，完整错误为14px可换行内容 |

已有工具协议仅有running/complete/error，保持该语义；不把错误文字匹配成独立取消状态。用户显式开关优先于默认，状态变化不强制打开或关闭已选择的内容。无显式选择时，进入error才按默认展开。等待交互/失败状态不得被窄屏隐藏。

展开后固定顺序为专门参数内容、执行结果、图片、嵌套调用摘要、其他字段、子工具。edit失败的例外顺序见§5.4。未知参数归“其他参数”，未知details归“其他详情”，均默认收起且显示JSON；已经专门展示的字段不重复出现。通用扩展工具保留现有回退，本轮不重写它们。

### 5.2 read

收起：`FileText / 读取 / src/app.tsx / 20–80 行 / ChevronRight`。只给offset时显示`从第20行`；只给limit时显示`前61行`；均未传时不添加范围。范围表示请求，展开显示精确`起始行 20 · 最多 61 行`，避免声称实际返回61行。

展开结构：

```text
│  ┌ src/app.tsx                         [路径复制] [内容复制] ┐
│  │ 起始行 20 · 最多 61 行                                    │
│  │ export function App() {                                   │
│  │   ...                                                    │
│  │ }                                                        │
│  │ [128 more lines in file. Use offset=81 to continue.]       │
│  └───────────────────────────────────────────────────────────┘
```

文本逐字保留，包括SDK附加的继续读取和截断段落，不解析或隐藏这些尾部信息。第一轮read不加行号，因为当前output把文件内容和提示文字拼在同一字符串，不能把提示算作文件行；也不从磁盘重读。read不做语法高亮，使用当前纯代码展示，保证输出原文、空白与选择行为一致。

图片位于文本块之后，沿用现有图片预览和打开能力。只有图片时省略空文本块，路径与请求范围作为图片上方12px信息行。文本结果为空字符串时显示“空内容”；没有文本或图片且仍运行时不显示空结果，结束且没有任何结果时显示“无输出”。错误文本使用14px正文与destructive，不套语法或行号。

truncation详情若存在，以12px信息行保留已提供的实际行数、字节数、限制及截断原因；未映射字段仍归其他详情。原文中的截断提示保留，结构化详情不再重复整段相同说明。

### 5.3 write

收起：`FileOutput / 写入 / src/lib/greeting.ts / 3 行 / ChevronRight`。行数只计算content；空字符串为0行，末尾单个换行不多算一行，内部空行保留。

展开：完整路径作为代码块标题，content直接作为14px代码，左侧从1开始的12px行号。使用CodeBlock已有lineNumbers能力，复制取原content，不含行号且保留末尾换行。内容缺省且仍运行时等待；明确空字符串显示“空内容 · 0 行”，允许复制空字符串。

结果文本位于代码块之后，用12px/18px muted文字逐字保留，可换行；超过6行使用max-height:108px的滚动区。成功回执不再套一个“输出”代码框。错误以14px/destructive置于内容块前，内容块仍表示尝试写入的内容。标题动作始终为“写入”，不推测新建或覆盖。第一轮不引入写前文件快照、语言高亮或格式化。

### 5.4 edit

收起：`FilePenLine / 编辑 / src/lib/greeting.ts / 2 处 / ChevronRight`。第一轮固定使用替换段数，不显示增删行统计，避免对SDK两种差异格式重复计数；明确完整替换请求时才显示段数。

成功：首块完整路径标题，内容优先details.patch，其次details.diff。只展示一种差异，不同时展示两套；有patch时details.diff仍可在“其他详情”取得。diff使用单列，不做左右分栏；增行背景muted及`+`，删行背景destructive/10及`−`，保留正负号，颜色不是唯一依据。第一轮不新增绿色主题色、不做字符级高亮。块头与hunk头使用12px muted，代码14px/22px，不合成文件行号。

```text
│  ┌ src/lib/greeting.ts                    [路径复制] [补丁复制] ┐
│  │ @@ -1,3 +1,3 @@                                             │
│  │   export function greeting(name: string) {                   │
│  │ −   return `你好，${name}`                                   │
│  │ +   return `你好，${name}。`                                 │
│  │   }                                                         │
│  └─────────────────────────────────────────────────────────────┘
│  Successfully replaced text in src/lib/greeting.ts.
│  ▸ 替换内容 · 2 处
```

patch的`---`/`+++`文件头按原文保留为中性12px行，不作增删代码；`@@`为中性底色。空字符等异常内容或无法识别的diff直接纯文本展示，不删行；复制始终得到原始patch/diff。firstChangedLine存在时块头附`首处第N行`，无点击跳转或文件编辑器暗示。

完整请求保留在默认关闭的“替换内容 · N处”内。按请求顺序逐段排列：`替换前 · 1 [复制]`、oldText代码块、`替换后 · 1 [复制]`、newText代码块，然后第二段。每段单列，空字符串显示“空内容”，不把替换片段标为整文件diff。此处行号关闭。没有实际差异时直接默认展开这些片段；运行中也使用片段，块上方12px标签“待应用”。

失败：先显示完整错误，再显示默认展开的请求片段；旧partialResult的diff保留在其他详情中。成功执行结果仍在差异之后原样保留，采用write的短回执样式。历史单段oldText/newText形状与现有edits[]分别读取，其他形状回退通用展示。

### 5.5 Agent bash

收起：`Terminal / 执行 / pnpm typecheck / [状态] / ChevronRight`。展开固定两块，命令在上、输出在下：

```text
│  ┌ 命令 · 超时60s                                     [复制] ┐
│  │ pnpm typecheck                                            │
│  └───────────────────────────────────────────────────────────┘
│  ┌ 输出                                               [复制] ┐
│  │ > huan typecheck                                          │
│  │ > pnpm -r typecheck                                       │
│  └───────────────────────────────────────────────────────────┘
│  完整输出  /tmp/pi-bash-123.log                       [复制路径]
```

命令14px等宽、保留换行、允许长单词折行；不把装饰性`$`加入复制。timeout只有显式传入时展示，缺省不推测。输出14px等宽，保留缩进并横向滚动；不加行号、不解析为Markdown、不执行ANSI控制序列。

当前HarnessToolViewPart未独立提供退出码或执行耗时，故Agent bash保留原始错误与结果，不解析输出末句猜测这些数据。非零退出的原始文本与error状态完整保留。已存在的fullOutputPath以12px可换行路径及复制按钮显示；SDK输出中的附加提示也保留。未知details继续可查。

运行中没有输出时不显示空框；已完成但输出为空时显示“无输出”。partial结果使用“输出中”块标题，最终替换为“输出”。错误保留命令和完整输出，输出块使用现有destructive边框，正文foreground以便阅读，错误状态与原始错误内容足以表达原因。

### 5.6 用户Shell

沿用§5.5命令/输出块尺寸和复制规则，差别精确限定为来源布局：

```text
                                      ┌─────────────────────────┐
                                      │ Terminal ! git status  ▾│
                                      └─────────────────────────┘
                       ┌ 命令                            [复制] ┐
                       │ git status --short                     │
                       └────────────────────────────────────────┘
                       ┌ 输出                            [复制] ┐
                       │ M src/app.ts                           │
```

### 10.5 ANSI纯空白背景修正
