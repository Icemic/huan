## 1. 目标与范围

`@huan/mcp` 复用 `<agentDir>/mcp.json` 和可信项目 `<cwd>/.pi/mcp.json`，沿用 Pi 的 mcpServers、覆盖和 exposure 语义。OAuth 凭据与日志仍为 `<agentDir>/huan/mcp-auth.json` 和 `<agentDir>/huan/mcp.log`，不读取或修改 Pi 的同名认证/日志文件。huan 专属设置未来单独存储，不在共享字段中引入不同含义；本次不新增专属设置文件或字段。

不读取、迁移或回退合并原 `<agentDir>/huan/mcp.json` / `<cwd>/.huan/mcp.json`；开发阶段无需迁移，且尚无运行时用户消费这些路径。只改配置路径与相关测试/说明，不推进连接、认证或 GUI，不加载个人配置/凭据。

## 2. 行为与并发边界

配置加载/保存指向与 Pi 相同文件，保留原文与未知字段。持久启停/exposure 变化会影响 Pi 后续加载；保存不自动操作任何 live runtime，临时重连等运行行为仍独立。未来 GUI 编辑必须标明共享影响，保存和应用分开。仅读配置不会启动进程、插值/执行命令、认证或联网。

未信任项目不触碰项目文件；保留目标和受管目录组件的符号链接拒绝、字节上限、revision 与串行原子保存。用户目标现为 agentDir 的直接子文件，目录安全检查须适应，不能误建 huan 配置目录。根 agentDir/cwd 符号链接仍允许，不扩大沙箱承诺。

同进程规范化路径写队列可串行多个 store；revision 可拒绝读取后已被 Pi/外部编辑器修改的旧提交。与 Pi TUI 同时写同一文件的跨进程 read-check-rename 仍有竞态窗口：当前没有双方共同遵守的锁协议，不新增伪跨进程锁、不承诺原子 CAS。避免同时编辑，冲突时重读；外部变更须重新加载，不自动合并。后续 runtime 接入沿用已有 `.pi/mcp.json` 信任检测，no-resources 缓存仍须在应用前重新核实。
