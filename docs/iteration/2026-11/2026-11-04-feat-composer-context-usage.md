# 输入区上下文用量与直接压缩

日期：2026-11-04。分类：feat。基线：`573dfb9`。完成状态以[roadmap](../../roadmap.md)为准。

## 1. 目标与范围

在输入区发送按钮左侧增加28px ghost图标按钮，以环形进度展示当前活动分支的上下文占用。点击立即打开，鼠标停留600ms打开同一Popover；内容包含上下文用量/窗口、百分比、横向进度、本会话累计输入/输出/缓存读取/缓存命中率和立即压缩按钮。

用户确认颜色区间：小于60%使用primary，60%至小于80%使用warning，80%及以上使用destructive。环形与横向进度保持一致。未知用量显示中性色及“—”，压缩后等待下一次响应更新，不显示成0%。

`/compact [可选提示词]`改为拦截后直接执行既有压缩接口，提示词作为customInstructions，不发送普通聊天、不打开运行面板。浮窗按钮复用相同压缩动作，无提示词且保留未发送草稿。原运行面板手动压缩入口与自动压缩设置保持。

## 2. 设计与所有权

- 使用现有官方shadcn/Base UI Popover及Trigger的openOnHover、delay=600；保留点击、键盘、触屏与移入内容操作，沿用主题/圆角/动效。
- 常驻环形读取已有服务端metadata.contextUsage；累计统计按需复用getThreadDetails，区分活动分支与全文件累计（含压缩历史、其他分支和委派usage）。浏览器业务状态归现有实例级Zustand，不新建普通会话缓存或逐token扫描历史。
- 累计输入按SDK未缓存input显示，缓存命中率为cacheRead/(input+cacheRead+cacheWrite)。分母为0时显示“—”；现有协议不区分provider未报告缓存与报告0，界面只展示已有用量记录的统计，不宣称provider独立命中率测量。
- 压缩动作固定发起会话与提示词，不读旧面板残留草稿；结果不写入已切换目标。模型运行、压缩及结构操作中禁止重复压缩；服务端闸门仍为权威。失败明确显示，取消沿用原入口。
- 已有会话的百分比由服务端给出，显示可超过100%，进度绘制限制0至100%；无会话/窗口未知时仍显示未知而非伪造精确值。浮窗读取失败保留错误提示。

## 5. 压缩取消与消息展示修订方案（已确认）

用户反馈命令提交后停止按钮变灰、命令留在输入框，且两个新入口缺少消息区进度/结果。此前测试只验证压缩完成后的命令处理及旧面板取消，未覆盖命令发起后的停止可用性。用户已确认本节方案，统一使用同一条状态行随执行结果更新，成功行可展开摘要；取消、失败是同一行的终态，不另建第二套提示。保存范围按§5.3第4项实施。

### 5.1 原因

- builtin命令分支一直await压缩完成，期间busy=command:compact；停止按钮也按此busy禁用。consumeCommandText发生在await之后，导致命令在运行期间残留。
- 现有compaction_start/end与快照已覆盖活动状态，但浏览器只保留活动标志及失败原因，没有保留取消结局。
- 成功摘要已有pi-compaction-summary展示。Pi的buildContextEntries将最新compaction置于模型上下文开头，huan直接采用session.messages，因此摘要不在本次操作的消息区末尾。Pi TUI另外调整了展示顺序。

### 5.3 建议设计

1. compact命令通过本地检查后，按捕获的草稿版本立即消费命令，并解除composer全局busy；请求及结果由会话状态持有。停止动作使用独立忙状态。发起后失败或取消不把旧命令自动写回新草稿，错误由消息行显示。
2. 消息区展示压缩状态行，所有手动入口及自动压缩共用：进行中“正在压缩上下文…”并提供“取消”；成功“上下文已压缩”，可展开既有摘要；取消“压缩已取消”；失败“压缩失败”及必要错误。输入区停止按钮也保持可用，复用现有stop；状态行取消调用现有abortThreadCompaction。
3. 扩充既有服务端compaction快照，携带当前/最近一次操作标识、结果及消息位置关联；事件和快照更新同一会话事实，浏览器仅投影。成功关联Pi现有compaction entry，展示层调整至操作顺序，替换进行中状态，不重复渲染开头摘要。不改变模型上下文、JSONL或树关系；自动压缩后继续响应时，结果位于后续响应前。
4. 成功摘要沿用Pi持久记录，刷新/重启可见；当前操作及最近一次失败/取消由服务端live快照提供，刷新/重连可见，不另建永久操作日志。服务重启后不保留失败/取消行。此范围已确认。

### 5.4 实施与验证

修订已实现：命令在本地检查后立即消费捕获版本，不等待压缩完成；输入区停止和消息行取消调用现有取消接口。所有入口以服务端compaction事件/快照显示结果，不再在浮窗或运行面板重复显示完成/取消/失败。

服务端保存operationId、结果和消息锚点，成功关联Pi entry；开始快照与刷新保持进行中位置，失败/取消仅在live记录保留。成功摘要的锚点独立于后续操作，取消新操作不会把旧摘要移回开头；切换分支时排除另一分支的结果。浏览器投影在操作边界拆开助手消息组，状态行位于保留消息之后、后续回复之前，不改变SDK模型上下文。

主agent独立review并亲自修复上述定位、分支有效性、刷新锚点、草稿处理和未开始失败提示。曾误将review修复委派回worker，用户指出后已中止，后续修复与验证由主agent执行。自动压缩定向验证使用SDK的完整摘要路径，包含较早历史与边界轮次两次摘要请求；测试在后续响应前关闭自动压缩，避免低阈值引起连续压缩。

最新定向验证：8文件134项单测、19条不同Chromium、全仓类型与30个代码文件Biome通过。浏览器挂起摘要后验证命令即时清空、停止可用、消息行取消、运行中刷新仍可取消、后来草稿保留；成功后摘要只显示一次、可展开并位于后续回复前，刷新不重复。旧面板取消、Shell和命令流程保持通过。失败/取消重启不保留、成功冷重启重建、旧成功后再次取消和压缩前分支切换由SDK单测覆盖。

日志位于本机Temp的`huan-compaction-final-unit-4.log`、`huan-compaction-final-types-2.log`、`huan-compaction-final-e2e.log`；最终请求失败提示修正后重跑7条上下文/运行流程通过，见`huan-compaction-final-e2e-2.log`。未执行全仓测试/build，未读图；可选协议字段扩充不改变版本18。

### 5.5 定向验收

SDK挂起压缩请求时，验证命令立即清空、停止可点并取消；单独按钮与旧面板显示同一状态行。成功后末尾结果只出现一次，可展开摘要，刷新后不重复；失败/取消及刷新中途状态正确，后来编辑的草稿不被覆盖。自动压缩覆盖状态行与继续响应的先后关系，不把压缩行加入模型消息。
